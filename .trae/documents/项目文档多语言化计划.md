# Bukit 项目文档多语言化计划

## 目标
为项目所有文档增加 **英文 (en)** 和 **马来文 (ms)** 版本，使每份文档都具备三语言（en / zh-CN / ms）覆盖。

---

## 一、命名与组织规范

沿用项目现有的多语言命名约定：
- `FILENAME.md` —— 英文（默认）
- `FILENAME.zh-CN.md` —— 简体中文
- `FILENAME.ms.md` —— Bahasa Melayu

对于文件名本身为中文的章节（如 `01-快速开始.md`），处理策略：
- 将该文件视为 `zh-CN` 版本 → 重命名为 `01-quick-start.zh-CN.md`
- 创建英文主文件 `01-quick-start.md`
- 创建马来文版本 `01-quick-start.ms.md`
- 同步更新所有交叉引用链接

1. 读取中文原文件

4. 重命名中文文件：`XX-中文名.md` → `XX-英文slug.zh-CN.md`

## 四、翻译原则

1. **技术术语保持原样**：CLI 命令、文件路径、代码片段、类名、方法名、YAML 键名不翻译
2. **中文文件名处理**：重命名为英文 slug 主文件 + .zh-CN.md / .ms.md 后缀
3. **交叉引用同步更新**：每个阶段完成后更新所属 README 中的链接
4. **保留 Front Matter**：如文件包含 YAML Front Matter（`---`），保持结构，翻译值
5. **代码块不翻译**：所有 ``` 代码块内容保持原样
6. **马来文翻译质量**：使用正式马来文 (Bahasa Melayu baku)，避免口语化

## 五、风险评估

| 风险 | 缓解措施 |
|------|----------|
| 翻译量巨大（~8,700 行），成本高 | 分阶段执行，AI 辅助翻译 + 人工审校 |
| 中文文件重命名导致 Git 历史丢失 | 使用 `git mv` 保留历史关联 |
| 交叉引用遗漏 | 各阶段完成后运行全仓链接检测脚本 |
| 马来文技术术语无标准译法 | 采用英文术语 + 马来文解释的方式 |
