# P2 Publish Audit Completion Spec

## Goal

Complete P2 by making Bukit's machine-readable and trust audit a first-class
publish audit surface, while preserving SEO/GEO reports as compatibility and
derived views.

## Current State

- `PublishDocument` exists and is used during SEO audit report construction.
- Builds write `.bukit/publish-audit-report.json`, `.bukit/geo-report.json`,
  and `agent-manifest.json`.
- `bukit publish audit` and `bukit publish diff` are registered, but
  `PublishCommand` delegates to `SeoCommand`.
- The publish report is currently created by replacing the SEO report schema
  URL in serialized JSON.
- Publish issue codes already exist for semantic HTML, trust, and
  representation gaps.

## Requirements

- Publish audit report models must be distinct from `SeoAudit*` models.
- `.bukit/publish-audit-report.json` must be serialized through a
  `PublishAuditReportJsonContext`, not generated by string replacement.
- Publish audit rules must be grouped into focused pure rule classes.
- `bukit publish audit/diff` must resolve `.bukit/publish-audit-report.json`
  by default and must not delegate to `SeoCommand.RunAsync`.
- `bukit seo audit/diff` may still validate publish reports when users pass an
  explicit `--report`, but SEO default resolution should prefer SEO reports.
- Documentation and skills must describe publish audit as the primary
  machine-readability and trust audit surface.

## Non-Goals

- Do not implement the P3 projection registry.
- Do not add per-document JSON or Markdown representations.
- Do not remove `seo-report.json` or `geo-report.json`.
- Do not introduce new NuGet dependencies.

## Compatibility Strategy

Existing `seo.*`, `geo.*`, and `publish.*` issue codes remain stable.
`seo-report.json` remains available under `.bukit/seo-report.json`.
`geo-report.json` remains a derived view for GEO readiness.
CLI diff budget semantics remain unchanged.

## Quality Requirements

- Follow Red -> Green -> Refactor for `.cs` logic changes.
- Keep changed `.cs` files at or below 600 lines.
- Update user-facing docs in English, Chinese, and Malay when CLI behavior is
  described.
- Run targeted tests and the repository quality gate before completion.
