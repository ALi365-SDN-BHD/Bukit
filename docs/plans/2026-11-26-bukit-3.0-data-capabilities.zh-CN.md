# Bukit 3.0 通用数据能力（F1～F13）

状态：设计稿。日期：2026-11-26。所属方案：[Bukit 3.0 重构设计方案](2026-11-24-bukit-3.0-architecture-design.zh-CN.md)。功能清单见 [功能超集对照](2026-11-24-bukit-3.0-feature-parity.zh-CN.md)。

## 目的

关系多、派生数据多的站点，应该能直接从数据源构建，不需要自建一层转换程序去预先算好关联、列表、SEO 字段和图片。2.0 的通用数据能力规划为此列出了 F1～F13 共 13 个功能点，3.0 必须全部覆盖。

## 规则

沿用功能超集对照的规则：

1. 只记录功能点，也就是用户能做到的事。
2. 不参考、不引用、也不考虑 2.0 的代码实现、架构和业务逻辑。
3. 不对齐参数。配置项、字段和模板里的名字都由 3.0 重新设计。
4. 下文的边界要求是功能的一部分，3.0 用自己的方式满足，并各有测试。

## 功能点

### F1 内容源保留结构化字段

- 用户能做到：对象和对象数组形式的字段，原样进入内容图，模板按路径取值。任何内容源都一样，同一个模板对不同内容源的结果相同。
- 值的类型在各内容源之间一致，例如列表元素是否保留数字。
- 规范形状有上限：最大深度、大小上限、键顺序规则固定。超限的字段被丢弃并报告诊断，严格模式下构建失败。诊断只写字段名和键路径，不写值。
- 隐私：字段白名单和敏感字段剔除也作用于嵌套的键，不只看顶层字段名。
- 嵌套值里出现平台私有的文件标识时有确定的处理规则，不会把私有标识发布出去。

### F2 引用字段

- 用户能做到：声明“某集合的某字段引用另一个集合的条目”，构建时解析成目标条目，模板直接拿到目标的标题、网址和字段，不用自己查找。
- 引用可以写在数组里，也可以写在嵌套路径里（例如每天的景点）。嵌套引用同时提供两种结果：按原结构分组，以及打平去重。
- 目标可以是出页面的内容，也可以是数据模式的记录，或者不出页面的条目（见 F13）。
- 解析结果可以写回页面字段（例如图片键解析成文件路径），SEO、分享图和搜索索引都能用到。
- 目标不存在时，按内容模型校验级别报错或告警。

### F3 反向索引

- 用户能做到：基于 F2 的引用声明，在目标条目上得到“引用了它的条目”列表，以及条目个数（例如城市页列出经过这里的路线）。
- 可以限制条数。列表按引用方集合的顺序排列，同一个引用方只出现一次。多个内容源拼成一个集合时，顺序规则要写明。
- 结果在构建阶段算好，模板不必遍历，SEO、搜索索引和小程序数据也能用。

### F4 命名查询

- 用户能做到：在站点配置里声明命名查询，结果作为站点级数据给模板使用，不再需要预先生成的列表文件。
- 操作是一组封闭的集合：筛选（等于、包含、有无反向引用）、稳定排序、按枚举定义顺序排序、去重、分组（数组字段按“包含”分组，组可以按给定的值列表固定顺序和取值）、取前几条。
- 查询名区分大小写的规则要明确，大小写不同但其余相同的名字不能互相覆盖。
- 依赖当前页面参数的查询不在范围内，由模板完成。

### F5 相关内容按自定义字段打分

- 用户能做到：相关内容可以按任意自定义字段的共同元素个数乘权重打分；可以只在同一集合内比较；阈值可以为 0。
- 结果带上目标的标识和网址，模板能取到卡片要的完整数据。
- 同分时按集合顺序，结果稳定。

### F6 按发布版本读取

- 用户能做到：远程内容源的筛选值可以引用环境变量，CI 在构建时注入要读取的发布版本。
- 变量没有设置或为空时构建失败，不能退化成不带条件的查询，也不能静默读到 0 条后构建成功。
- 环境变量只能用在筛选值里。会拼进请求地址的配置（环境标识、表名）不接受变量。
- 文档写明安全取舍：读取凭据能看到的未上线版本，在构建成功之前就能被公开读到。多条件筛选用视图解决，或者以后扩展。

### F7 远程内容源离线快照

- 用户能做到：联网构建时录制远程内容源的数据，之后离线构建，不用凭据，也不访问网络。功能清单里已有这一项，这里补充数据能力相关的要求。
- 快照只存可以公开的字段，文件只存不含令牌的标识。
- 来源设置变了（模式、字段映射、字段列表、筛选、排序、条数上限），离线构建和配置校验都要失败，不能回放旧数据。
- 离线结果和联网结果一致：联网时被丢弃并报告的字段，离线时同样被丢弃，诊断也照样报告。
- 快照内容被手工改过时，不能借此发布录制时不存在的链接。

### F8 枚举标签来自内容模型（可选）

- 用户能做到：字段的枚举可以同时定义取值和显示标签，按定义顺序给模板使用，CMS 的字段定义可以成为唯一来源。
- 标签保留定义顺序，不按键名重新排序。标签的命名空间不和数据源的名字冲突。

### F9 集合级派生字段

- 用户能做到：在集合上声明派生字段，构建时用模板表达式从本条内容和 F2 解析出的引用生成，例如 SEO 标题、摘要、描述、分享图、替代文字。SEO、分享图、结构化数据和搜索索引读到的都是派生后的值。
- 两种模式：字段为空时才生成，或者总是生成。
- 提供受控函数处理常见规则，例如按显示宽度截断、为描述补句。
- 表达式不能遍历其他集合；有单独的循环上限和输出长度上限，超限时在生成过程中就失败；出错时按内容模型校验级别处理。
- 固定文化格式，数字和日期格式与系统区域设置无关，同一份数据重复构建逐字节一致。
- 派生出来的值同样要通过内容模型的必填和规范校验。

### F10 数据索引的键名

- 用户能做到：数据索引接受 i18n 文案常用的键名，包括点号分层、驼峰大写、连字符和加号，并有明确的范围切分规则。
- 如果选择不放宽，就要在文档里写明键名规则，并提供迁移指引。

### F11 数据模式的媒体资产

- 用户能做到：数据模式的记录（图库、人物照片、评价图片）也能把文件字段换成可公开的链接并本地化，本地文件名稳定。
- 响应式尺寸由图片处理生成，模板不依赖写死的派生文件名。
- 换链失败时用占位图，并报告诊断；平台私有的文件标识不会出现在产物里。
- 离线构建时，已经公开的存储地址原样保留；只有带签名的地址才需要换成录制时的结果。

### F12 permalink 引用字段值

- 用户能做到：permalink 模式可以引用内容字段的值（例如景点网址里含所属城市）。
- 值按网址规则清洗。整数值按整数写入，带小数的数值不进入网址。
- 构建时检查生成的网址是否重复。

### F13 同一集合部分条目出页面

- 用户能做到：给集合设定出页面条件。不满足的条目不出页面，不进 sitemap、feed 和搜索，但仍然在内容图里，可以被 F2 引用、被 F4 查询、出现在 F3 的反向列表里。
- 条件的值比较规则明确，例如整数和整数形式的小数视为相等。
- 不出页面的条目没有网址，所以不产生链接，也不生成派生字段；模板拿到的引用结果能区分这种情况。

## 横向要求

每个功能点都要满足：

- 增量构建：引用、反向引用和查询结果的变化要能触发读过它们的页面重建。目标页的标题、网址或反向列表变了，引用方页面也要重建。3.0 由任务引擎的字段级依赖记录自动满足，不允许为此退化成全量重建。
- 确定性：所有排序都是稳定排序，并写明同值的规则；对象键顺序有统一规则；表达式求值用固定文化格式。同一份数据重复构建逐字节一致。
- 隐私：新暴露到公开产物的数据（嵌套字段、引用目标的字段、查询结果、派生值）都只能来自白名单字段。
- 多语言：引用、反向索引、查询和派生字段都按语言分别计算。引用目标在当前语言缺失时，按建模阶段的回退规则处理，跨语言的校验看全站文档。
- 诊断：配置错误在校验阶段报出，并指明配置位置；内容问题按内容模型校验级别报错或告警。

## 完成标准

1. F1～F13 的每一项在 3.0 里都有归属，并各有至少一个测试证明它可用。
2. 上面每条边界要求都有对应的行为测试。
3. 某个部件动工之前，它负责的功能点必须已列在本表里。

## 局限

- 本文依据 2.0 的功能规划和用户文档整理，只描述用户能做到的事，没有参照 2.0 的实现。2.0 实现中定下的具体取舍（例如 F1 的类型规则、F10 选哪种做法），由 3.0 重新决定，并在对应部件的设计里写明。
- F8 在 2.0 规划里是可选项，3.0 仍按功能列入，可以分期交付。
