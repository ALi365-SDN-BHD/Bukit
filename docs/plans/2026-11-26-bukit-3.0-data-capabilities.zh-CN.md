# Bukit 3.0 通用数据能力（F1～F13）

状态：设计稿。日期：2026-11-26。所属方案：[Bukit 3.0 重构设计方案](2026-11-24-bukit-3.0-architecture-design.zh-CN.md)。功能清单见 [功能超集对照](2026-11-24-bukit-3.0-feature-parity.zh-CN.md)。

## 目的

关系多、派生数据多的站点，应该能直接从数据源构建，不需要自建一层转换程序去预先算好关联、列表、SEO 字段和图片。2.0 的通用数据能力规划为此列出了 F1～F13 共 13 个功能点，3.0 必须全部覆盖。

## 规则

沿用功能超集对照的规则：

1. 只记录功能点，也就是用户能做到的事。
2. 不参考、不引用、也不考虑 2.0 的代码实现、架构和业务逻辑。
3. 不对齐参数。配置项、字段和模板里的名字都由 3.0 重新设计。
4. 下文的边界要求是功能的一部分，3.0 用自己的方式满足，并各有测试。

## 从条目到页面的执行顺序

以 `v2.2.9` 的[出页条件、引用与派生字段](https://github.com/ALi365-SDN-BHD/Bukit/blob/v2.2.9/guide/user/04-site-yaml-config.md#derived-fields)为行为基线。建模阶段保留全部条目，准备各语言的标识、公开字段和查找键。下列步骤在路由阶段内依次完成；产出阶段读取冻结的路由与最终数据。

| 顺序 | 读取与产出 |
|---|---|
| 1 · F13、F12 | 用条目已有字段判定出页资格。对有页条目生成最终 URL 并检查冲突；无页条目保留标识与公开字段，URL 为空。 |
| 2 · F2、F3 | 有页来源按语言解析引用；每个目标返回公开字段与步骤 1 确定的 URL。按同一条已解析的边建立反向列表，截取条数前计算去重总数。此时选取的是派生前字段。图上另可按原始引用键查询无页来源，见 F13。 |
| 3 · F9 | 只为有页条目计算文本派生值，可以读取本条目的字段、已解析引用及反向列表。派生完成后，再对最终值做一次必填、枚举、规范字段和记录关系校验。 |
| 4 · F4、冻结结果 | 命名查询读取最终字段与反向列表，也能选中无页记录。发现模型、列表、模板、订阅、搜索和小程序投影均使用最终值与各自的可见性规则。 |

配置校验拒绝让 F9 提供出页条件、permalink 占位字段或覆盖路由保留字段、引用输出和非文本类型字段。F2 选取目标字段时不追随目标自身的引用或后续派生结果。由此，两个页面可以相互引用已经确定的 URL，求值不需要递归。

**验收示例。** 一条有页面的路线引用两个景点：A 有页面，B 只有数据。F2 给出 A 的实际 URL 和 B 的名称、空 URL；只有 A 的页面反向列表出现这条路线。若另一条无页路线也记录了 A 的键，它只出现在显式的反向数据查询里，A 的页面引用总数仍为一。F9 可用两者的名称生成路线摘要，F4 可按该摘要筛选路线。把 A 改为无页后，旧页面被移除，引用仍能读到 A，URL 变为空；读取该 URL 或受影响查询的页面应当重建，最终产物与全量构建一致。

## 功能点

### F1 内容源保留结构化字段

- 用户能做到：对象和对象数组形式的字段，原样进入内容图，模板按路径取值。任何内容源都一样，同一个模板对不同内容源的结果相同。
- 值的类型在各内容源之间一致，例如列表元素是否保留数字。
- 规范形状有上限：最大深度、大小上限、键顺序规则固定。超限的字段被丢弃并报告诊断，严格模式下构建失败。诊断只写字段名和键路径，不写值。
- 隐私：字段白名单和敏感字段剔除也作用于嵌套的键，不只看顶层字段名。
- 嵌套值里出现平台私有的文件标识时有确定的处理规则，不会把私有标识发布出去。

### F2 引用字段

- 用户能做到：声明“某集合的某字段引用另一个集合的条目”，构建时解析成目标条目，模板直接拿到目标的标题、网址和字段，不用自己查找。
- 引用可以写在数组里，也可以写在嵌套路径里（例如每天的景点）。嵌套引用同时提供两种结果：按原结构分组，以及打平去重。
- 目标可以是出页面的内容，也可以是数据模式的记录，或者不出页面的条目（见 F13）。
- 解析结果可以写回页面字段（例如图片键解析成文件路径），SEO、分享图和搜索索引都能用到。
- 按 slug 或指定的文本、整数键匹配；相同整数的不同数值写法匹配同一目标。缺失目标、重复键、形状不符或输出字段已存在时，按引用方集合的校验级别报告。缺失目标的引用省略，已有内容字段保留。重复目标键在校验策略允许继续时采用当前语言下按稳定输入顺序遇到的第一个目标。正向引用、反向页面列表和显式数据反查均归到这个目标。

### F3 反向索引

- 用户能做到：基于 F2 的引用声明，在目标条目上得到“引用了它的条目”列表，以及条目个数（例如城市页列出经过这里的路线）。
- 可以限制条数。列表按引用方集合的顺序排列，同一个引用方只出现一次。计数按截取前的去重总数；没有引用的目标页面得到空列表和零。多个内容源拼成一个集合时，沿用该集合的稳定顺序。
- 同一集合的两项关系声明若会写入同一个输出字段（含计数字段），配置校验失败。若与目标页面已有字段重名，保留原字段，按目标集合的校验级别报告冲突；正向引用的字段冲突归引用方集合。
- F3 提供两种结果。默认页面列表只收录有页来源，写在有页目标上。显式数据反查按同一关系的原始键返回有页和无页来源，可查询当前语言可见的有页或无页目标。两种结果都按来源条目标识去重，沿用来源集合的稳定顺序，先计算总数再限量。结果在构建时算好，供模板、SEO、搜索和小程序投影直接使用。

### F4 命名查询

- 用户能做到：在站点配置里声明命名查询，可选择要返回的公开字段，结果作为站点级数据给模板使用，不再需要预先生成的列表文件。
- 操作是一组封闭的集合：筛选（等于、包含、有无反向引用）、稳定排序、按枚举定义顺序排序、去重、分组（数组字段按“包含”分组，组可以按给定的值列表固定顺序和取值）、取前几条。分组时限量逐组生效，例如两个各有三条以上记录的月份各取三条，共得六条。缺少排序字段或未列入指定顺序的值在升降序中都排最后。按字段去重时先展开数组，文本忽略大小写，保留首次出现的值与顺序；去重和分组互斥。
- 仅大小写不同的查询名在配置校验时报错；空集合得到空结果。
- 按反向关系筛选必须指明查询目标集合上声明的反向关系，关系不存在或属于其他集合时配置校验失败。默认“有反向引用”读取页面的反向计数字段，判断是否大于零；无该字段视为零，遇到 F3 的同名冲突时读取保留下来的页面字段。
- 要把无页来源计入查询，须在命名查询中显式选择该关系的**反向数据记录**。此时按数据反查的去重总数筛选目标，也可取回对应的来源记录。默认页面计数与显式数据总数独立；无页来源返回公开字段与空 URL。两种查询均限于当前语言可见的条目。
- 依赖当前页面参数的查询不在范围内，由模板完成。

#### F3/F4 反查验收

下表以同一语言的一条已声明关系为例，景点 A 有页面，来源集合内 R1 排在 R2 之前。计数字段没有同名冲突。表中“命中”表示 F4 用指定口径筛选时返回 A。

| 指向 A 的路线 | 默认页面列表 / 总数 | 默认查询 | 显式数据记录 / 总数 | 显式查询 |
|---|---|---|---|---|
| 无 | 空 / 0 | 不命中 | 空 / 0 | 不命中 |
| 只有无页 R2，在数组中写了两次 A | 空 / 0 | 不命中 | R2（空 URL）/ 1 | 命中 |
| 有页 R1 和无页 R2，各写了两次 A，列表限一条 | R1 / 1 | 命中 | R1 / 2 | 命中 |

取消第三例的限量后，显式数据列表依次返回 R1、R2。若再移除 R1 对 A 的引用，增量构建须产生第二例的结果：读取默认查询的页面移除 A，读显式列表的页面仍显示 R2，与全量构建一致。R2 始终不生成页面链接或 F9 字段。

### F5 相关内容按自定义字段打分

- 用户能做到：相关内容可以按任意自定义字段的共同元素个数乘权重打分；可以只在同一集合内比较；阈值可以为 0。
- 结果带上目标的标识和网址，模板能取到卡片要的完整数据。
- 同分时按集合顺序，结果稳定。

### F6 按发布版本读取

- 用户能做到：远程内容源的筛选值可以引用环境变量，CI 在构建时注入要读取的发布版本。
- 变量没有设置或为空时构建失败，不能退化成不带条件的查询，也不能静默读到 0 条后构建成功。
- 环境变量只能用在筛选值里。会拼进请求地址的配置（环境标识、表名）不接受变量。
- 文档写明安全取舍：读取凭据能看到的未上线版本，在构建成功之前就能被公开读到。多条件筛选用视图解决，或者以后扩展。

### F7 远程内容源离线快照

- 用户能做到：联网构建时录制远程内容源的数据，之后离线构建，不用凭据，也不访问网络。功能清单里已有这一项，这里补充数据能力相关的要求。
- 快照只存可以公开的字段，文件只存不含令牌的标识。
- 每个来源独立录制。离线回放先核对有效查询，筛选或排序与录制时不同即失败（S2）。
- **Notion** 在同一查询结果内可以离线更改字段映射。例如已批准且已录制中文、英文两个标题属性，将标题从中文改映射为英文后，无凭据、零网络请求即可用英文标题重建。若启用已审阅配置锁定，先应用锁定的映射和字段许可；离线配置不能扩大录制时的公开范围，所需属性未录制或未获准时报告失败。
- **CloudBase** 的模式、字段映射、文件字段、发布字段集合、已解析的发布版本、排序、存储桶或条数上限实质改变时，离线构建和配置校验都要失败。发布字段名单仅调整顺序可重放，更改字段拼写或大小写要重新录制。
- 离线结果和联网结果一致：联网时被丢弃并报告的字段，离线时同样被丢弃，诊断也照样报告。
- 快照内容被手工改过时，不能借此发布录制时不存在的链接。

### F8 枚举标签来自内容模型

- 用户能做到：字段的枚举可以同时定义取值和显示标签，按定义顺序给模板使用，CMS 的字段定义可以成为唯一来源。
- 同一枚举拒绝重复值，支持全局和按集合定义。标签保留定义顺序，不按键名重新排序。标签的命名空间不和数据源的名字冲突。

### F9 集合级派生字段

- 用户能做到：在集合上声明派生字段，构建时用模板表达式从本条内容和 F2 解析出的引用生成，例如 SEO 标题、摘要、描述、分享图、替代文字。SEO、分享图、结构化数据和搜索索引读到的都是派生后的值。
- 同一条目的规则按声明顺序求值。每步只读到当时的字段值，成功写入后立即对后续规则可见。例如先派生摘要，再用摘要生成 SEO 描述，后者应读到新摘要。
- 结果为去掉首尾空白的文本。默认填充只处理缺失或空字段，结果为空则跳过写入；覆盖模式总是写入，包括空结果。
- 提供受控函数处理常见规则，例如按显示宽度截断、为描述补句。
- 语法错误在配置校验时报告；运行出错保留原字段。表达式禁用时钟与随机函数，不能遍历其他集合；有单独的循环上限和输出长度上限，超限时在生成过程中就失败；出错时按内容模型校验级别处理。
- 固定文化格式，数字和日期格式与系统区域设置无关，同一份数据重复构建逐字节一致。
- 派生出来的值同样要通过内容模型的必填和规范校验。

### F10 数据索引的键名

- 用户能做到：数据索引接受 i18n 文案常用的键名，包括点号分层、驼峰大写、连字符和加号，并有明确的范围切分规则。
- 键区分大小写；校验必填键时以第一段识别范围，后续点号属于键名。模板和查询可以读取完整键名。

### F11 数据模式的媒体资产

- 用户能做到：数据模式的记录（图库、人物照片、评价图片）也能把文件字段换成可公开的链接并本地化，本地文件名稳定。
- 响应式尺寸由图片处理生成，模板不依赖写死的派生文件名。
- 换链失败时用占位图，并报告诊断；平台私有的文件标识不会出现在产物里。
- 离线构建时，已经公开的存储地址原样保留；只有带签名的地址才需要换成录制时的结果。

### F12 permalink 引用字段值

- 用户能做到：permalink 模式可以引用内容字段的值（例如景点网址里含所属城市）。
- 值按网址规则清洗。整数值按整数写入，带小数的数值不进入网址。
- 缺失、空白或清洗后为空的占位值报错；构建时检查生成的网址是否重复。

### F13 同一集合部分条目出页面

- 用户能做到：给集合设定出页面条件。条件读取顶层字段，字段缺失的条目不出页。无页条目保留在内容图中，可被 F2 引用、被 F4 查询；集合的页面列表、sitemap、feed 和搜索均排除它。
- 文本忽略首尾空白和大小写，布尔值按真假比较，整数和整数形式的小数视为相等。
- 页面反向列表沿用基线语义：只有有页来源贡献页面引用，只有有页目标得到反向页面列表。无页条目没有出站页面链接、页面反向列表或 F9 派生值。3.0 仍支持原设计中含无页来源的反向数据列表：F3 按原始引用键提供显式的数据反查，F4 可读取这些记录；无页来源的 URL 为空。F3 的默认页面列表及其总数只统计有页来源。

## 横向要求

每个功能点都要满足：

- 增量构建：引用、反向引用和查询结果的变化要能触发读过它们的页面重建。目标页的标题、网址或反向列表变了，引用方页面也要重建。3.0 由任务引擎的字段级依赖记录自动满足，不允许为此退化成全量重建。
- 确定性：所有排序都是稳定排序，并写明同值的规则；对象键顺序有统一规则；表达式求值用固定文化格式。同一份数据重复构建逐字节一致。
- 隐私：新暴露到公开产物的数据（嵌套字段、引用目标的字段、查询结果、派生值）都只能来自白名单字段。
- 多语言：引用、反向索引、查询和派生字段都按语言分别计算。默认只匹配当前语言和该语言可见的共享数据，其他语言独有的目标按缺失处理。全站校验可以查阅各语言文档，但不能据此生成跨语言链接。
- 诊断：配置错误在校验阶段报出，并指明配置位置；内容问题按内容模型校验级别报错或告警。

## 完成标准

1. F1～F13 的每一项在 3.0 里都有归属，并各有至少一个测试证明它可用。
2. 上面每条边界要求都有对应的行为测试。
3. 某个部件动工之前，它负责的功能点必须已列在本表里。

## 局限

- 本文依据 2.0 的功能规划和用户文档整理，只描述用户能做到的事，没有参照 2.0 的实现。2.0 实现中定下的具体取舍（例如不同内容源如何统一 F1 的值类型），在满足本表基线行为的前提下由 3.0 决定，并在对应部件的设计里写明。
- F8 在 2.0 规划里是可选项，v2.2.9 已提供此功能，3.0 必须覆盖，可以分期交付。
