Phase 4：Deploy provider contract 收紧
目标

明确 1.0 Core deploy 只支持 GitHub Pages。

当前 DeployConfig 仍有：

public string? Provider { get; init; }

但 DeployCommand 实际固定使用：

new GitHubPagesDeployProvider()

4.1 决策

本轮采用方案 A：

保留 deploy.provider 字段，但 1.0 只允许空值或 github-pages。

不得新增其他 provider。

4.2 修改 ConfigValidator

在部署配置验证逻辑中增加：

if (config.Deploy?.Provider is { } provider &&
    !provider.Equals("github-pages", StringComparison.OrdinalIgnoreCase))
{
    throw new ConfigException(
        "deploy.provider must be 'github-pages' in Bukit 1.0.",
        DiagnosticCode.ConfigInvalidValue);
}

如果已有 ProviderValidators.ValidateDeployConfig，优先放入该方法，不要分散逻辑。

4.3 修改 DeployCommand

在 DeployCommand 中，在创建 provider 前增加显式检查：

var providerName = deployConfig.Provider ?? "github-pages";
if (!providerName.Equals("github-pages", StringComparison.OrdinalIgnoreCase))
{
    Console.Error.WriteLine("deploy.provider must be 'github-pages' in Bukit 1.0.");
    return 2;
}

然后继续使用：

new GitHubPagesDeployProvider()
4.4 测试要求

新增或更新测试：

DeployProviderDefaultsToGitHubPages
DeployProviderRejectsUnsupportedProvider
DeployDryRunDoesNotRequireGitHubToken
DeployNonFastForwardFailsWithoutForce
DeployNonFastForwardForceRequiresExplicitForce

如果 non-fast-forward 难以单元测试，可以先覆盖 provider validation 与 dry-run。
