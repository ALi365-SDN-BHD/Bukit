# Bukit 3.0 功能超集对照（基线 v2.2.9）

状态：设计稿。初稿：2026-11-24。基线复核：2026-11-28。所属方案：[Bukit 3.0 重构设计方案](2026-11-24-bukit-3.0-architecture-design.zh-CN.md)。

## 规则

1. 3.0 只记录 2.0 的功能点，也就是用户能做到的事。3.0 的功能必须是 2.0 的超集，任何一个功能点都不能遗漏。
2. 不参考、不引用、也不考虑 2.0 的代码实现、架构和业务逻辑。
3. 不对齐参数。命令、选项、配置项、字段和模板里的名字都由 3.0 重新设计；2.0 里不合理的参数可以舍弃，只要它背后的功能在 3.0 里仍然做得到。
4. Labs 和官方插件的功能同样在范围内，可以分期交付，不可以丢弃。
5. 本文只列功能，不列 2.0 的参数名，也不要求逐个参数给出 3.0 的对应项。

## v2.2.9 基线增补

基线固定为 `v2.2.9`（`b7418dd0`）。下面按用户能观察到的结果，补充原盘点与该版本之间的差额。各行都是恢复实施后的验收条件；历史盘点的参数数量不能作为完成率。版本依据见 [v2.2.9 发布记录](https://github.com/ALi365-SDN-BHD/Bukit/blob/v2.2.9/CHANGELOG.md)。

| 能力与 3.0 归属 | 可观察的验收行为 |
|---|---|
| 数据关系与部分出页 · 路由、模板（F2、F3、F12、F13） | 同一集合可同时有页面和纯记录。按已有字段判定出页，用文本或整数生成 URL 并检查冲突。嵌套引用既保留分组也能打平去重；可选取目标公开字段，无页目标的 URL 为空。重复目标键报告后按稳定顺序选首个目标；反向字段重名的声明在配置校验时失败，目标原有同名字段保留并按目标集合策略诊断。默认页面反向列表只统计有页来源，F4 显式数据反查还可返回无页来源；两种结果各自去重，截取前计算各自的总数。 |

| 逐语言站点与分类 · 建模、路由、发现模型 | 语言可覆盖站点标题、分隔符、描述和组织资料；未覆盖的组织字段沿用默认，根级合并产物使用站点身份。分类名称、描述和词条标题前缀可本地化，分类、归档及分页产物携带生成语言。词条按类别、翻译键和页码配对；无键按 URL，同语言重键告警并按 URL 回退。根级只发布一份 robots.txt，保留各语言的 404，单个共享资源只输出一份。 |
| 跨语言索引与结构化数据 · Discovery | noindex 和按策略不收录的空列表页从双向 hreflang、分享语言候选和 sitemap 候选中排除。Open Graph 输出有效地区码及 alternates，无法确定的语言省略其地区标签并告警。sitemap URL 按 UTF-8 百分号编码；更新日期按站点时区。JSON-LD 区分站点语言与页面语言，文章时间按站点时区精确到秒，审计比较同一时刻。面包屑依次呈现首页、URL 祖先、分类父页和当前页，相同祖先只出现一次。 |
| 文章、作者与分享图 · Discovery、主题 | 文章类型按页面、集合、站点、默认顺序选取，文章子类型同样接受发布者和审计规则。作者署名或标识可关联含网址的作者资料。本地分享图的宽、高和 MIME 类型可供头部标签和主题使用；WebP 分享图报告预览兼容性告警。 |
| 订阅与搜索 · Discovery、搜索输出 | 集合进入站点订阅与发布独立集合订阅可分别控制；只有一个订阅集合时默认避免生成重复订阅。RSS 作者使用 Dublin Core 创建者，单一有效语言标注频道语言，混合语言不标；正文链接、图片及 srcset 的站内地址补成绝对 URL。内嵌搜索在合并模式下仍默认搜索本语言。内嵌界面和入门主题的搜索页先读取 JSON，成功只发一次请求；读取失败才允许加载同源脚本索引。跨域索引只按数据读取，无法取得有效索引时显示“搜索不可用”。内置搜索页使用无 BOM 的 UTF-8。 |
| 机器可读表示 · Discovery、发布审计 | Markdown 与全文聚合保留标题层级、段落、嵌套列表、引用、链接和代码围栏；正文不能伪造元数据或文档分隔符。Markdown 与 JSON 的发布时间、更新时间、作者和公开原文地址一致；审计只从 Markdown 元数据区取这些值。代理清单区分真实发布与修改时间，生成时间取最近变更；列出内容的各版本，并列出 sitemap 收录的首页、集合及分类路由，根清单涵盖各语言，未配置站点绝对地址时列表路由为空。 |
| 响应式媒体 · 媒体处理、HTML 输出 | 静态 WebP 原图可生成尺寸候选，跳过动画、已有变体及配套同名 WebP。媒体图片按 EXIF 方向补显示尺寸，首幅保留即时加载、后续默认懒加载；尊重作者指定的尺寸、加载和 sizes 属性。生成的 sizes 同时适用于 WebP 候选，懒加载可自动选宽。可省去 JPEG/PNG 的原格式缩小副本而保留原图回退；静态主题资源不生成用不到的原格式副本。PNG 变体保留透明度，完全不透明图可去掉透明通道；常用尺寸转换无需外部工具，不支持的 AVIF 转换安全跳过。 |
| 报告与发布边界 · 报告库、部署扩展 | 构建报告使用项目相对路径，工作区或暂存绝对路径不进入报告。部署及公开校验和清单排除内部状态、各语言私有目录和图片新鲜度文件；本地审计与增量构建仍可使用它们。3.0 私有报告写在发布根之外，消费者从构建 JSON 获取路径。 |

## 修正的设计

盘点发现三处设计为了简化而丢了功能，一处前后矛盾，已修正：

| 功能 | 原设计 | 修正后 |
|---|---|---|
| 单页只从订阅、搜索或站点地图中的某一种里排除 | 所有输出共用一个可索引性结论 | 可索引性给出默认结论；另有按输出类型的单页排除，两者都记录理由 |
| 内容标题、搜索引擎标题、最终文档标题三者分离 | 不存在第二份标题 | 发现模型保留三种标题及其来源，各输出按约定取用 |
| Labs 功能 | 不进首版，需要时以扩展回归 | 属于 3.0 范围，以扩展形式分期交付，不丢弃 |
| 父主题解析 | 两处说法矛盾 | 构建和诊断按名称从本地主题目录解析；本地缺失即报告。注册表扩展提供显式安装，路径形式和穿越一律拒绝 |

## 完成标准

1. 既有功能清单和 v2.2.9 基线增补中的每一项功能在 3.0 里都有归属。
2. 某个部件动工之前，它负责的功能必须都已列在表里，并各有至少一个测试证明它可用。这是合入条件，与继承测试、性能门禁并列。
3. 舍弃一个参数之前，确认它背后的功能仍然做得到；做不到就不能舍弃。
4. 迁移工具只转换有对应的部分，并报告被舍弃的参数。

## 局限

- 盘点依据的是 2.0 的用户文档。文档没写到的隐含行为不在其中。
- 功能清单是从参数粒度的盘点归纳出来的，归纳时可能把两个不同的功能合成了一项。发现时补入本表。
