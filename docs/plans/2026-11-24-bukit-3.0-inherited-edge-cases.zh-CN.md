# Bukit 3.0 继承的边界情况清单

状态：从 2.0 测试只读梳理得到的原始清单，供 [Bukit 3.0 重构设计方案](2026-11-24-bukit-3.0-architecture-design.zh-CN.md) 引用。日期：2026-11-24。

用途：3.0 继承 2.0 的测试经验，不继承 2.0 的架构、代码和实现思路。清单里出现的 2.0 测试文件名和测试名只作为证据，不是 3.0 的设计依据。

局限：大部分条目依据测试名归纳，未逐条核对断言；阈值和错误码写入 3.0 规格前要回到证据测试核对。各部分的“未覆盖”小节列出了没有梳理的范围。

本文由两份独立梳理的报告合并而成，编号和级别标记各自独立：第一部分用 `[C]`、`[I]`、`[M]`，第二部分用【关键】、【重要】、【次要】。

## 第一部分：Bukit 2.0 测试沉淀的边界情况（Engine / Shared / Routing / Rendering / Theme / Architecture / Stage7DiskFull）

范围：`tests/Bukit.Engine.Tests`、`Bukit.Engine.Abstractions.Tests`、`Bukit.Shared.Tests`、`Bukit.Routing.Tests`、`Bukit.Rendering.Tests`、`Bukit.Theme.Tests`、`Bukit.Architecture.Tests`、`Stage7DiskFull`，以及 `guide/dev/core-safety-reliability-invariants.md`、`guide/user/20-core-safety-reliability.md`。

方法：只读。先盘点全部约 4400 个测试方法名，再按名称挑出边界/失败/平台/竞态/安全类测试，打开其中一部分核对断言与用例数据（路由、slug、URL 安全、事务、磁盘满、循环上限、JSON 输出、配置校验、点文件等）。其余条目依据测试名与辅助文档归纳，未逐条读断言——这些条目在证据后标 `(名)`。没有运行任何测试或构建。

标记：`[C]` 关键（重写时踩到会丢数据、越权读写或发布错误内容）/ `[I]` 重要 / `[M]` 次要。证据路径均相对仓库根目录。

### 1. 输出清理安全

1. `[C]` 给定要清理的目录是项目根、用户主目录或文件系统根，系统必须拒绝递归删除。证据：tests/Bukit.Engine.Tests/OutputDirectoryCleanerTests.cs（EnsureCanClean_Root/FilesystemRoot/UserHome_Throws）`(名)`
2. `[C]` 给定清理目标路径中任一段为 `.git`，或位于项目根之外，系统必须拒绝删除。证据：OutputDirectoryCleanerTests.cs（EnsureCanClean_GitSegment_Throws）；guide/user/20-core-safety-reliability.md
3. `[C]` 给定清理目标经由项目根以下的符号链接/重解析点到达，系统必须拒绝删除。证据：OutputDirectoryCleanerTests.cs（EnsureCanClean_SymlinkBelowRoot_Throws）`(名)`
4. `[C]` 给定非空且没有“本工具产出”标记的目录，系统必须拒绝清理并在错误信息里说明如何修复；空目录可以删除；标记存在也不能绕过前三条。证据：OutputDirectoryCleanerTests.cs；tests/Bukit.Engine.Tests/BuildPlannerCleanErrorTests.cs `(名)`
5. `[I]` 给定用户主目录路径的大小写变体，系统必须按当前平台的路径比较规则判断是否为同一目录。证据：OutputDirectoryCleanerTests.cs（EnsureCanClean_UserHomeCaseVariant_FollowsPlatformComparison）`(名)`
6. `[C]` 给定显式 clean 命令、配置驱动的清理、正常构建清理、未完成构建的恢复清理这四个入口，系统必须对它们应用同一套安全判定。证据：guide/dev/core-safety-reliability-invariants.md（F-01）；BuildPlannerCleanErrorTests.cs（RecoveryAutoClean…）`(名)`
7. `[I]` 给定输出目录中存在本工具从未登记过的用户文件（包括用户自放的 robots.txt），系统在增量构建、内容撤回、首次失败后都必须保留它们，且永不把它们认领为自己的产物。证据：tests/Bukit.Engine.Tests/SiteEngineLifecycleTests.cs（UntrackedFileSurvivesSuccessfulWithdrawal、UntrackedRobotsIsNeverClaimed、FirstFailurePreservesUntrackedFiles…）`(名)`
8. `[I]` 给定旧版本留下的产物清单但输出目录没有标记，系统必须仍然要求标记后才清理。证据：SiteEngineLifecycleTests.cs（LegacyManifestRequiresMarker）；tests/Bukit.Engine.Tests/I18nRootLayoutTests.cs（LayoutSwitch_WithoutOutputMarkerRefusesToClean）`(名)`

### 2. 源目录与输出目录的相互保护

9. `[C]` 给定内容源目录与输出目录相同，或任一方包含另一方，系统必须在写入任何文件之前失败——即使该目录里已有旧的输出标记。证据：tests/Bukit.Engine.Tests/BuildTransactionTests.cs（Begin_RejectsConfiguredSourceEqualToOutputBeforeAnyWrite、…DespiteOldMarker、…ContainmentBothDirections）
10. `[C]` 给定源目录通过符号链接或大小写别名指向输出/缓存目录，系统必须按物理身份识别冲突并拒绝。证据：BuildTransactionTests.cs（Begin_RejectsSymlinkedAndCaseAliasedSourceIdentity）
11. `[I]` 给定源目录位于自定义缓存目录或指标文件目标之内，系统必须拒绝；给定仅名称相似（前缀相同的兄弟目录）或彼此独立的目录，系统不得误判为冲突。证据：BuildTransactionTests.cs（Begin_RejectsSourceInsideCustomCacheOrMetricsTarget、Begin_DoesNotTreatSimilarNamesOrIndependentSourcesAsConflicts）
12. `[I]` 给定把项目根本身配置为内容源（即使带精确 include 规则），系统必须拒绝并提示使用专用目录。证据：BuildTransactionTests.cs（Begin_RejectsProjectRootSourceEvenWithPreciseIncludes）
13. `[I]` 给定远程内容源的可写缓存目录与本地内容源目录重叠（含相对路径别名、子目录符号链接），系统必须拒绝；内存型内容源恰好有名为 `output` 的内容时不得误拒。证据：tests/Bukit.Engine.Tests/SiteEngineSourceProtectionTests.cs `(名)`

### 3. 构建事务、失败与恢复

14. `[C]` 给定渲染、聚合、报告、校验任一阶段失败或被取消，系统必须让正式输出目录、受管缓存与指标文件逐字节保持构建前状态，且不留下临时事务目录。证据：tests/Bukit.Engine.Tests/Stage7FailureTests.cs；Stage7PluginFailureTests.cs；BuildTransactionTests.cs（FailureAndCancellationLeaveTargetsUnchanged）
15. `[C]` 给定输出卷在渲染写入中途真实写满（clean 与非 clean 两种模式），系统必须以 I/O 错误失败，正式输出和缓存不变，事务残留为零。证据：tests/Stage7DiskFull/Stage7DiskFullTests.cs（RealOutputVolumeFull_PreservesFormalOutputAndCache）
16. `[C]` 给定进程在提交阶段的两次目录交换之间死亡，下一次构建必须能依据记录恢复出完整的旧输出或新输出，不能停在半交换状态。证据：BuildTransactionTests.cs（NextBuildRestoresOutputAfterProcessDiesBetweenDirectoryMoves、RecoveryHandlesInstalledNewOutputParent）
17. `[C]` 给定恢复时发现备份缺失或目标已被改动，系统必须停止并交给人工处理，不得猜测性覆盖；未知的待处理临时文件必须保留。证据：BuildTransactionTests.cs（NextBuildRecoversWhilePreservingUnknownJournalTemporaryFile）；guide/user/20-core-safety-reliability.md
18. `[C]` 给定事务记录的临时文件位置被人放了符号链接，系统必须不通过该链接覆盖用户文件；创建记录文件时不得替换已存在的文件。证据：BuildTransactionTests.cs（JournalTemporarySymlinkNeverOverwritesUserFile、JournalCreationDoesNotReplaceExistingFile）
19. `[I]` 给定提交时目录交换失败，系统必须回滚；回滚也失败时必须保留备份并报告其位置。证据：BuildTransactionTests.cs（SwapFailureRollsBackAndPreservesBackupWhenRecoveryFails）
20. `[I]` 给定提交成功但备份清理失败，系统必须只告警并保留新输出，不得撤销提交。证据：BuildTransactionTests.cs（CleanupFailureDoesNotUndoCommit）
21. `[I]` 给定事务记录属于另一个输出目录、或同仓库内另一个站点，系统必须拒绝复用前者并忽略后者；记录属于仍存活的进程时不得当作崩溃残留去恢复。证据：BuildTransactionTests.cs（BeginRejectsJournalForDifferentOutput、FindOtherJournalsIgnoresOtherSitesInSameRepository、BeginAllowsJournalOwnedByLiveProcess）
22. `[I]` 给定失败的构建，系统不得为原本不存在的缓存/指标路径创建祖先目录；给定目标路径的某个祖先是文件，必须在创建任何目标之前失败。证据：BuildTransactionTests.cs（FailureDoesNotCreateMissingCacheOrMetricsAncestors、FileAncestorConflictIsRejectedBeforeCreatingAnyTarget）
23. `[I]` 给定输出内含指向输出内部或其他受管目标的绝对路径链接，提交后这些链接必须仍指向正式位置而非暂存位置；报告与增量标识里出现的也必须是正式路径。证据：BuildTransactionTests.cs（CommitPreservesAbsoluteLinksAcrossTargetsAndWithinOutput、Transaction_IncrementalIdentityAndReportsRemainFormal）
24. `[I]` 给定只读模式的缓存，构建期间被修改时提交必须失败；缺失的只读缓存不得被凭空创建。证据：BuildTransactionTests.cs（ReadonlyCacheRemainsMissingOrPreservesNestedSubtree）
25. `[I]` 给定上次构建的状态文件损坏、状态未知、版本号来自未来或没有版本号，系统必须一律视为“上次构建未完成”；写入“开始”状态失败时必须保留旧状态。证据：tests/Bukit.Engine.Tests/BuildRecoveryTrackerTests.cs `(名)`
26. `[I]` 给定构建被取消，系统不得写出半份构建报告。证据：tests/Bukit.Engine.Tests/SiteEngineIntegrationTests.cs（BuildAsync_CancellationDoesNotWritePartialBuildReport）`(名)`
27. `[I]` 给定 Markdown 文件在读取元数据与读取正文之间被改动，系统必须在提交前失败并保留旧输出。证据：SiteEngineIntegrationTests.cs（BuildAsync_MarkdownBodyChangedBetweenMetadataAndBody_FailsBeforeCommitAndKeepsOldOutput）
28. `[M]` 给定远程内容缓存的条目是原子的且按编辑时间寻址，构建中止时这类缓存可以保留，而同一次构建下载的媒体必须回滚。证据：BuildTransactionTests.cs（NotionCacheSurvivesAbortWhileMediaRollsBack）
29. `[M]` 给定资源释放阶段抛错，构建不得被报告为成功；内容正文存储在成功、失败、取消三种结局下都必须恰好释放一次。证据：SiteEngineLifecycleTests.cs（DisposeFailureCannotComplete）；tests/Bukit.Engine.Tests/SiteEngineBodyStoreLifetimeTests.cs；ContentPipelineTests.cs `(名)`

### 4. 并发构建与资源占用

30. `[C]` 给定两个进程（或嵌套构建）要写同一路径、或一方路径是另一方的祖先/后代，后来者必须失败并提示资源忙；只读使用者之间可以共存，读者与写者在两个方向上都冲突。证据：BuildTransactionTests.cs（HierarchicalConflictAndRelease、ReadOnlyReadersCoexistButWritersConflictInBothDirections、SeparateProcessCannotClaimOverlappingResource）
31. `[I]` 给定通过别名（符号链接、尚不存在的路径尾部）指向同一资源，系统必须识别为同一资源并判冲突。证据：BuildTransactionTests.cs（AliasWithMissingSuffixConflicts）
32. `[I]` 给定嵌套构建，内层不得把外层的正式资源重新归类为暂存；互不相交的嵌套构建结束后外层的路径映射必须恢复。证据：BuildTransactionTests.cs（NestedBuildCannotReclassifySharedFormalResourceAsParentStaging、NestedDisjointBuildRetainsItsOwnMappingAndRestoresParentScope）
33. `[C]` 给定并行渲染，输出的公开字节必须与串行渲染完全一致；多语言构建在任意语言并发度下输出一致。证据：tests/Bukit.Engine.Tests/Stage7ParallelTests.cs；SiteEngineIntegrationTests.cs（BuildAsync_LanguageJobs_ProducesIdenticalOutputRegardlessOfConcurrency）`(名)`
34. `[I]` 给定外层已并行处理多个列表，内层并行度必须降为 1，使峰值并发不超过配置的总预算；多语言构建须遵守全局并发预算。证据：tests/Bukit.Engine.Tests/SpecialListRendererNestedParallelTests.cs；PageRenderDispatcherNestedParallelTests.cs；SiteEngineIntegrationTests.cs（MultiLanguageBuildRespectsGlobalConcurrencyBudget）`(名)`
35. `[I]` 给定并行渲染多个页面且模板使用组件/区块，页面之间不得串数据；模板不得修改跨页面共享的模型（新增键、数组赋值都必须失败且不泄漏），数组函数作用于共享数组时必须返回副本。证据：tests/Bukit.Rendering.Tests/ScribanTemplateRendererTests.cs（…MultiplePagesInParallel_NoCrossContamination）；SharedModelTests.cs `(名)`
36. `[I]` 给定增量批次渲染中途取消，系统不得把部分更新合入增量状态；整批完成前更新对外不可见。证据：SpecialListRendererNestedParallelTests.cs（Incremental_CancellationDoesNotMergePartialUpdates、…DoesNotExposeUpdatesUntilBatchCompletes）`(名)`
37. `[I]` 给定媒体下载并发上限，系统必须把它作用于实际下载调用（跨文档、HTML 正文与媒体字段共享）；重试不得增加许可数，取消与失败必须归还许可。证据：guide/dev/core-safety-reliability-invariants.md（F-07）
38. `[M]` 给定并发写日志（JSON 格式）或并发累加构建指标，每条事件必须完整、计数必须精确。证据：tests/Bukit.Shared.Tests/ConsoleLoggerTests.cs（JsonFormat_ConcurrentCalls_PreserveEveryCompleteEvent）；tests/Bukit.Engine.Tests/BuildStageMetricsCollectorConcurrencyTests.cs `(名)`
39. `[I]` 给定启用跨语言共享资源，默认语言必须先于其他语言构建；默认语言失败时其他语言不得启动。证据：tests/Bukit.Engine.Tests/I18nSharedAssetsTests.cs（DefaultLanguageFailure_DoesNotStartOtherLanguages）；SiteEngineIntegrationTests.cs（SharedAssets_BuildsDefaultLanguageBeforeOthers）`(名)`

### 5. 输出归属与目标冲突

40. `[C]` 给定两类不同来源（静态文件、主题资源、本地化媒体、生成的主题变量样式、内容页/列表页、渲染型静态模板）要写同一目标，系统必须在写入任何发布文件之前失败。证据：tests/Bukit.Engine.Tests/AssetPipelineTests.cs（…SameDestination_FailsBeforeWriting）；SiteEngineIntegrationTests.cs（RenderedStaticAndAssetCollision_FailsBeforeAnyOutputWrite）`(名)`
41. `[C]` 给定一个产物需要路径 `a` 作为文件、另一个需要 `a/…` 作为目录，系统必须在写入前判为结构性冲突。证据：AssetPipelineTests.cs（FileAndDirectoryPrefixCollision…、DescendantAndFilePrefixCollision…）`(名)`
42. `[C]` 给定仅大小写不同的两个目标路径，系统必须按**输出卷实际的**大小写敏感性判断是否冲突，而不是按操作系统名称推断。证据：AssetPipelineTests.cs（…CaseVariantCrossCategoryTargets_FollowFileSystemSemantics）；guide/user/20-core-safety-reliability.md
43. `[I]` 给定父主题与站点（子主题）在同一类别内提供同名文件，系统必须保留“站点覆盖父主题”，不视为冲突。证据：AssetPipelineTests.cs（ParentAndSiteStatic/AssetsSameDestination_PreservesSiteOverride）；SiteEngineIntegrationTests.cs（ChildThemeAssetsOverrideParentThemeAssets）`(名)`
44. `[C]` 给定两条内容路由的 URL 或输出路径重复（含规范化后重复），或静态 HTML 与内容路由撞车，系统必须在渲染前失败。证据：tests/Bukit.Engine.Tests/RoutePipelineTests.cs（Execute_WhenContentRoutesConflict…、…ListRoutesConflict…）；SiteEngineIntegrationTests.cs（DuplicateContentRouteUrl_FailsBeforeRendering、StaticHtmlRouteConflictsWithContentRoute_FailsBeforeWrite）；ListRouteGraphTests.cs `(名)`
45. `[I]` 给定增量构建中某目标的归属从一类来源换到另一类（含仅大小写变化的迁移），系统不得把当前有效的输出当旧产物删掉；旧文件挡住新目录（或反之）时必须移除这个结构性障碍。证据：AssetPipelineTests.cs（IncrementalOwnerMovesFromStaticToTokens…、IncrementalCaseVariant…）`(名)`
46. `[I]` 给定被跳过的输入（目录符号链接、点目录），系统不得在归属清单里为它留下“幽灵”登记。证据：AssetPipelineTests.cs（SkippedDirectorySymlink_DoesNotCreateGhostClaim、SkippedDotDirectory_DoesNotCreateManifestOwner）`(名)`
47. `[I]` 给定静态 HTML 被当模板渲染，系统不得再用原始拷贝覆盖渲染结果；父子主题同名时只渲染一次。证据：SiteEngineIntegrationTests.cs（StaticHtmlTemplateOutput_IsNotOverwrittenByRawCopy）；AssetPipelineTests.cs（Create_ChildRenderedStaticHtml_SuppressesParentAndChildRawCopies）`(名)`
48. `[I]` 给定用户提供了静态 robots.txt / sitemap / llms.txt 等与生成文件同名的文件，系统必须有明确规则（用户文件优先，或在拷贝前判冲突），且该规则忽略文件名大小写；大小写写错的 `Robots.TXT` 必须判冲突而不是悄悄替换。证据：I18nRootLayoutTests.cs（StaticRobots_OverridesGeneratedRobotsInBothDirections、StaticRobots_MiscasedNameConflicts…、StaticLlms_ConflictIgnoresFileNameCase、StaticRootOwnedFiles_ConflictBeforeCopy）`(名)`
49. `[I]` 给定生成型聚合输出（feed、搜索索引等）的路径会覆盖一个渲染页面或落到另一语言目录下，系统必须使构建失败。证据：I18nRootLayoutTests.cs（GeneratedOutputs_MayNotReplaceAPage、CollectionFeedPath_OntoARenderedPageFailsTheBuild、CollectionFeedPath_UnderAnotherLanguageFailsTheBuild）`(名)`
50. `[M]` 给定构建后第三方插件写出的任意文件，2.0 明确**不**纳入归属预检；3.0 需决定是否覆盖。证据：guide/dev/core-safety-reliability-invariants.md（F-03）

### 6. 符号链接与重解析点

51. `[C]` 给定默认配置，递归发现内容、静态文件、媒体、模板、数据文件、目录哈希、输出清单时，系统不得穿过目录符号链接/重解析点下探。证据：tests/Bukit.Engine.Tests/StaticFileServiceTests.cs；HashUtilTests.cs；AssetToolingSymlinkTests.cs；BuildReporterTests.cs（OutputInventories_DoNotIncludeFilesThroughDirectorySymlink）；tests/Bukit.Rendering.Tests/ScribanTemplateLinterTests.cs；DataFilesPluginTests.cs `(名)`
52. `[C]` 给定显式开启“跟随符号链接”，系统只能复制最终真实路径仍在源根之内的目标；指向根外、经由根外中间链接、指向敏感文件、形成环的链接都必须跳过；链式链接解析到最终目标再判断。证据：tests/Bukit.Engine.Tests/DirectoryCopyFollowSymlinksTests.cs；AssetPipelineTests.cs（FollowedSymlinkToSensitiveFile_IsSkipped、…ThroughExternalIntermediate…、FollowedDirectorySymlinkCycle_IsSkipped）`(名)`
53. `[C]` 给定文件在“枚举校验通过”之后、“打开读取”之前被替换成指向根外的符号链接（或其父目录被换成链接），系统必须失败且不写出，并保留已存在的目标文件。证据：tests/Bukit.Shared.Tests/PlatformSafeSourceFileOpenerTests.cs（Open_FileReplacedBySymlinkAfterEnumeration_FailsClosed、Open_ParentDirectoryLinkToOutside_FailsClosed）；tests/Bukit.Engine.Tests/DirectoryCopyTests.cs（SyncPlannedFile_WhenValidatedSourceIsRetargetedOutsideRoot_ThrowsBeforeWriting）`(名)`

### 最容易重踩的十条

1. **目标冲突按输出卷的实际大小写敏感性判断（#42）**——在 macOS 上开发、Linux 上发布的重写几乎一定会先用“按操作系统名判断”。
2. **校验与读取之间的替换竞态（#53、#54）**——“先检查路径再按路径打开”是最自然的写法，也正是漏洞所在。
3. **提交不是原子的，崩溃可能落在两次目录交换之间（#16、#17）**——需要可恢复的记录，而且恢复时不能猜。
4. **源与输出重叠要按物理身份、双向包含判断，旧标记不能当通行证（#9、#10）**。
5. **Windows 保留名与别名形式在所有平台都拒绝（#64）**——在 Unix 上开发时不会自己暴露，直到 Windows 用户检出或部署。
6. **带点的最后一段不等于文件（#66）**——`/docs/v1.0`、`/tags/node.js` 被当成文件是极常见的回归。
7. **模板依赖失效必须基于内容而非长度/时间戳，且覆盖布局链与 include（#91、#92）**。
8. **增量结果必须与全量逐字节一致，哈希超预算时宁可全量也不返回不完整哈希（#89、#98）**。
9. **从 HTML 提取文本时隐藏块不得泄露、也不得吞掉后文（#133）**——用正则剥标签的第一版实现会在这 25 个用例上大面积失败。
10. **默认语言在根目录时，语言代码成为保留的首段，且切换布局要清干净旧产物（#111、#114）**。

### 最容易重踩的十条

1. **F2 / F1 清理只删带自己标记的目录**：重写时最容易写成“配置里的输出目录就可以整个删”，一旦配置指错就是数据丢失。
2. **L7 插件超时要杀整棵进程树，并且读流有界**：只杀主进程时，握着管道的孙进程会让宿主永久挂起；E11 的 git 子进程是同一个坑。
3. **D1 + D2 + D3 本地服务器的路径判定**：编码穿越、符号链接别名、同前缀兄弟目录三类绕过各自独立，简单的前缀比较三样都挡不住。
4. **H3 元数据块非法时整篇不加载**：按“解析失败就当没有元数据”处理，草稿标记会丢，草稿直接上线。
5. **C3 + C4 错误信息不带机密、也不回显用户填错的值**：新实现几乎必然会把原始异常消息或 URL 拼进错误文本。
6. **I4 + K1 带认证或由内容驱动的请求不自动跟随重定向**：HTTP 客户端的默认行为就是跟随，令牌会被带到第三方，内网探测也会漏过。
7. **I3 分页必须防重复游标并设请求预算**：远端返回异常游标时，朴素的 while 循环不会结束。
8. **G1 + G3 产物提交是事务**：失败、取消、进程被杀、磁盘写满四种情况下都要保住上一份可用产物，并且只清理自己创建的东西。
9. **K5 + K6 签名地址的标识与过期处理**：把整条 URL 当缓存键会导致每次构建全量重下；对过期签名照常重试会白白耗时并刷出大量告警。
10. **B8 显式空值不等于未设置**：用“为空就取默认值”的写法会悄悄改变用户意图，部署仓库为空时回落到当前远端就是一例。

备选（同样高风险）：M4 不可重放操作先落盘意图；E3 被污染的 git 配置；I5 分钟精度的编辑时间导致缓存误命中；B2 多文档与重复键。
