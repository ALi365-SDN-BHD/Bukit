# AD03-R3～R6 受控治理设计

日期：2026-07-22

基线：`main@5632b1db`

实施分支：`codex/ad03-r3-r6`

## 1. 目标

在不改变 Bukit Core 1.x 公共 CLR 签名、配置 schema、插件协议、Notion API
版本、内容投影、HTML、关系链接或缓存格式的前提下，关闭 AD-03 两层拆分后的
四个残余治理问题：

- R3：canonical adapter 仍通过 `Bukit.Shared.Notion.NotionApiUrls` 兼容入口取
  Notion URL；
- R4：Engine 直接引用 `Bukit.Content.Notion` 项目和 adapter internals；
- R5：旧 renderer registry 复制 canonical 默认注册表，block compatibility mapper
  缺少新增类型穷尽性保护；
- R6：两个 canonical Notion 程序集虽已纳入公共面基线，但 1.x 分发定位未由活动
  契约明确约束。

## 2. 已批准定位

采用方案 A：

- `Bukit.Notion` 是 BCL-only、可在 Bukit 单仓内复用的 canonical 实现；
- `Bukit.Content.Notion` 是 Bukit Core 的 canonical 内容适配器；
- 两者在 1.x 都不是独立、受支持的 NuGet SDK；
- 两者的现有 public 类型继续遵守 `1.x-do-not-narrow / 2.0-review`，本任务不修改
  可见性、命名空间、程序集身份或公共签名；
- 是否形成外部 NuGet SDK，只能在后续独立产品化任务中决定。

## 3. R3：URL 所有权归一

`Bukit.Content.Notion` 中的 `NotionContentSource`、`NotionRelationResolver` 和
`NotionDatabaseSchemaResolver` 直接导入 `Bukit.Notion.NotionApiUrls`。旧
`Bukit.Shared.Notion.NotionApiUrls` 继续保留为 1.x facade，但 canonical adapter
不得反向依赖该 facade。

Architecture Tests 扫描 canonical adapter 生产源码，拒绝
`Bukit.Shared.Notion.NotionApiUrls` 和 `using Bukit.Shared.Notion;`。这不会移除
adapter 对 `Bukit.Shared` 的 `ILogger` 等现行依赖。

## 4. R4：Engine 与 adapter internals 解耦

保留公共 `INotionPageFetcher.FetchAsync(NotionApiClient, ...)` 原签名。该签名属于
1.x 公共面，本任务不引入替代接口，也不把 `NotionApiClient` 改成 canonical
transport 类型。

在 `Bukit.Content` 的现有 1.x compatibility assembly 中增加 internal
`NotionCompatibilityQueries`：

- 接收现有 `NotionApiClient`；
- 在程序集内部访问其 canonical transport；
- 调用 `Bukit.Content.Notion` 的 internal page query 和 database option reader；
- 将 adapter internal snapshot 映射为仅供 Core 程序集协作的 internal record；
- 保持调用方拥有并释放 `NotionApiClient`，不新增 client wrapper 所有权；
- 不改变 retry、限流、请求头、异常脱敏或取消传播。

Engine 的默认 page fetcher 和 taxonomy schema option 注入只使用上述 Content
compatibility service。完成后：

- `Bukit.Engine.csproj` 删除对 `Bukit.Content.Notion.csproj` 的直接引用；
- `Bukit.Content.Notion.csproj` 删除对 `Bukit.Engine`、`Bukit.Engine.Tests` 的
  `InternalsVisibleTo`；
- Engine 继续通过已有 `Bukit.Content` 引用取得 legacy public contract 和 internal
  compatibility service；
- `Bukit.Content → Bukit.Content.Notion` 的 1.x 兼容依赖保持不变，不产生依赖环。

## 5. R5：兼容实现单一所有权

旧 `Bukit.Content.Notion.NotionBlockRendererRegistry.CreateDefault()` 不再维护第二份
block type 注册清单，而是包装 canonical
`Bukit.Notion.Rendering.NotionBlockRendererRegistry.CreateDefault()`。公共默认构造器、
`Register`、custom transformer 和 remove 行为保持原样；旧 public renderer 类型也继续
保留，只是不再拥有默认注册表。

测试采用两层防回归：

1. Architecture Tests 断言 legacy registry 的默认工厂只委托 canonical factory，
   不再出现本地 `registry.Register(...)` 清单；
2. Shared compatibility tests 用反射发现 canonical 与 legacy `NotionBlock` 的所有
   concrete subtype，并与显式双向 round-trip fixture 对账。新增任一 subtype 而未补
   mapper case 时测试必须失败。

compatibility mapper 仍使用 AOT 友好的显式 type switch，不引入反射式运行时映射或
JSON DTO。

## 6. R6：1.x 单仓分发治理

在 `Bukit.Notion.csproj` 和 `Bukit.Content.Notion.csproj` 显式设置
`<IsPackable>false</IsPackable>`。Architecture Tests 同时拒绝 `PackageId`、
`GeneratePackageOnBuild` 和非 false 的 `IsPackable`。

活动文档 `guide/dev/public-api-governance.md` 增加 Notion assembly distribution
boundary，明确：

- CLR `public` 仍不是外部 SDK 承诺；
- 两个程序集只随 Core CLI 源码/构建图分发；
- 1.x 不得收窄当前公共类型；
- 独立打包、支持矩阵、SemVer SDK 承诺和安装文档必须另立产品化任务。

本任务不修改公共 API baseline，因为生产 public/protected surface 不发生变化。

## 7. 测试与实施顺序

按 R3 → R4 → R5 → R6 执行。每项遵守测试优先：先增加能暴露当前残余问题的测试，
确认失败，再做最小实现并运行相关测试。每个子项结束后仅运行：

```bash
bash scripts/checks/post-change-focused.sh -- <该子项变更路径>
```

父任务完成后，以 `5632b1db` 为 base，仅运行一次：

```bash
bash scripts/checks/post-change-targeted.sh --base 5632b1db -- <全部变更路径>
```

定向测试至少覆盖 `Bukit.Notion.Tests`、`Bukit.Content.Notion.Tests`、
`Bukit.Content.Tests`、`Bukit.Shared.Tests`、`Bukit.Engine.Tests` 和
`Bukit.Architecture.Tests` 中受影响测试。不得运行 full、release、`test-all`、
`smoke-all` 或整仓库解决方案测试。

## 8. 禁止事项与风险控制

- 不修改 1.x public signature、类型可见性、程序集身份或 namespace；
- 不修改配置 schema、插件协议、Notion API 版本或 HTTP/TLS 策略；
- 不改变写请求 retry 语义、`HttpClient` 所有权、Token header、限流实例边界、
  错误脱敏或取消传播；
- 不改变 Content 投影、HTML、关系链接、缓存 key 或缓存格式；
- 不新增反射 JSON 序列化；
- 不将 Importing 重新耦合到 Content/Engine；
- 不删除 1.x Shared/Content compatibility facade；
- 不新增 NuGet package metadata、发布 workflow 或安装文档；
- 不顺带处理 AD-01、AD-05、现有 analyzer baseline drift 或其他架构债务。

## 9. 完成判定

只有同时满足以下条件，R3～R6 才能关闭：

- canonical adapter 不再使用 Shared Notion URL facade；
- Engine 不再直接引用 adapter project，也不再获得 adapter internals friendship；
- legacy registry 默认清单只有 canonical 单一所有者；
- block mapper 对新增 subtype 有穷尽性失败保护；
- 两个 canonical Notion 项目显式不可打包，活动治理文档与测试一致；
- 所有现有公共签名及公共面 drift baseline保持不变；
- focused checks、一次 aggregate targeted、`git diff --check` 和独立只读复审完成；
- 若存在基线或环境失败，必须原样分类，不能以无关修复或抑制伪造通过。
