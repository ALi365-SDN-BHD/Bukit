# Bukit P0 资产流水线确定性设计

**状态：** 已批准设计，等待书面规格复核

**日期：** 2026-08-04

**范围：** 深度审计建议修复顺序中的 P0 资产问题

## 1. 目标

修复两个 P0 资产缺陷，同时保持既有产品语义：

1. SCSS 编译与图片预处理不得修改主题源码；所有外部工具只能写入本次构建独占的临时工作区。
2. 所有图片派生物必须在公共输出写入前进入统一输出所有权与冲突检查；after-build 阶段不得再次扫描并递归处理已经生成的图片。

完成后，同一源码、配置和工具链应产生同一组受清单管理的公共资产；多语言构建不得并发修改共享主题目录，也不得把上一次构建的派生物当成本次输入。

## 2. 当前基线与受控差距

当前 `main@ed467492` 已包含三项相关改进：

- `AssetSourceWorkspace` 在临时目录复制主题资产，并在其中运行 SCSS 与格式转换。
- `theme.scss.entryPoint`、`theme.scss.outputDir` 已接入编译和输出计划。
- 当前 after-build 图片插件已用文件名规则避免直接递归，并把尺寸变体登记为插件输出。

这些已完成部分应保留，不得重新实现或回退。剩余差距是：尺寸变体仍在公共 `dist/assets` 内生成，格式转换与尺寸生成分属两个阶段，尺寸变体没有在公共写入前参加 `AssetOutputPlan` 的全局冲突检查，且 `__image_srcsets` 没有生产消费者。

设计提交期间，工作树中存在与图片插件、外部工具运行器及其测试重叠的未提交改动。它们不属于本设计提交。后续实施开始前必须重新核对 HEAD 和工作树；不得覆盖、丢弃或暗中吸收这些改动。若重叠仍存在，实施在首个写入动作前停止并请求用户处置。

## 3. 范围

### 3.1 本轮包含

- 主题资产临时工作区的生命周期与源码只读约束。
- SCSS `entryPoint` 和 `outputDir` 的确定语义。
- 原图格式转换与尺寸变体的统一预处理。
- 派生资产的输出所有权、冲突检查、清单跟踪和增量删除。
- 移除内建 after-build 图片处理注册及无生产消费者的 `__image_srcsets` 数据。
- 与上述外部工具调用直接相关的超时、取消和临时文件清理合同。
- 仅覆盖这些行为的 Engine 专项测试和一次专项审查。

### 3.2 本轮不包含

- 审计报告中的恢复状态、主题验证器、Markdown 协议、Preview 安全等 P1 项。
- 审计报告事实修订、Core/Labs/WeChat 拆分等 P2 项。
- Labs、WeChat、发布、CI、门禁或历史参考目录的修改。
- 父主题资产的新编译语义、额外图片格式、HTML 自动改写或新的模板 API。
- 尺寸化 WebP/AVIF 笛卡尔组合、响应式图片组件或图片 CDN。
- 与 P0 资产合同无直接关系的重构和性能优化。

## 4. 确定的配置语义

### 4.1 SCSS 输入

- `theme.scss.enabled: false`：SCSS 文件按现有普通资产规则处理，本轮不改变该行为。
- `theme.scss.enabled: true` 且设置 `entryPoint`：只编译该文件。
- `theme.scss.enabled: true` 且未设置 `entryPoint`：编译主题资产目录中的全部 `.scss` 文件。
- `entryPoint` 必须是主题资产目录内的相对 `.scss` 路径；绝对路径、盘符相对路径、目录穿越、缺失文件均以配置错误失败。
- SCSS 启用时，`.scss` 源文件不进入公共输出，即使 Sass 缺失或单个编译失败也不回退为公开源码。

### 4.2 SCSS 输出

- `theme.scss.outputDir` 相对于最终构建输出根目录，而不是相对于主题资产目录。
- 输出保留输入文件在主题资产目录下的相对层级，只把扩展名改为 `.css`。
- 示例：`entryPoint: styles/site.scss` 与 `outputDir: assets/css` 产生 `dist/assets/css/styles/site.css`。
- `outputDir` 必须是构建输出根目录内的相对路径；绝对路径、盘符相对路径和目录穿越均失败。
- 未找到 Sass 或单文件编译失败时记录现有警告语义，只把实际成功且可读的 CSS 加入输出计划。

### 4.3 图片输入与输出

- 原始输入集合在任何图片派生物生成前一次性捕获，只包含主题资产工作副本中的 `.jpg`、`.jpeg` 和 `.png` 文件。
- 后续生成的文件不重新参与输入枚举，因此不依赖文件名猜测来阻止递归。
- `formats` 仅保留现有支持的全尺寸转换语义：为每个原图生成所配置的 WebP/AVIF。
- `sizes` 仅保留现有尺寸变体语义：为每个原图生成同扩展名的 `-<width>w` 文件。
- 不生成尺寸化 WebP/AVIF 组合。
- 示例：`hero.jpg`、`formats: [webp, avif]`、`sizes: [480, 768]` 的候选公共集合是：
  - `hero.jpg`
  - `hero.webp`
  - `hero.avif`
  - `hero-480w.jpg`
  - `hero-768w.jpg`
- 只有外部工具成功退出且临时输出存在、可读时，派生物才成为实际输出。失败或缺失的派生物不得被登记、投影或保留为本次所有物。

## 5. 架构

### 5.1 单一预处理工作区

`AssetSourceWorkspace` 继续作为主题资产预处理的唯一入口：

1. 为每次顶层构建建立不可复用的临时根目录。
2. 按现有点文件与符号链接策略把主题资产复制到工作副本。
3. 从工作副本捕获 SCSS 和原图输入集合。
4. 只在临时根目录内运行 Sass、格式转换和尺寸生成。
5. 返回只读使用的已准备资产描述，供所有语言变体规划和复制。
6. 顶层构建成功、失败或取消后在 `finally`/`Dispose` 路径清理整个工作区。

主题源码目录和公共输出目录都不是外部工具的目标。多语言变体可以并行读取同一份准备结果，但不得修改它。

### 5.2 两级输出声明

图片准备分为两个声明层次：

1. **候选声明：** 根据原图、`formats` 和 `sizes` 先计算目标相对路径。候选之间的同路径冲突必须在调用图片工具前失败，例如 `photo.jpg` 与 `photo.png` 同时声明 `photo.webp`。
2. **实际声明：** 工具运行后只保留成功派生物。实际声明与 Static、Assets、Media、Tokens、Render 的全部输出一起进入 `AssetOutputPlan`；任何精确或祖先/后代结构冲突都在公共写入前失败。

候选声明用于阻止歧义生成，实际声明用于确保失败产物不被错误拥有。两次检查之间允许写临时文件，但不允许写公共输出。

### 5.3 生成资产类别与执行

`AssetOutputPlan` 增加明确的 `GeneratedAssets` 类别。每个条目包含：

- 临时工作区内的已成功生成文件；
- 相对于最终输出根目录的目标路径；
- 生成资产类别和复制所需的受信源根/复制选项。

公共执行阶段在完整计划通过验证后，把 `Assets` 与 `GeneratedAssets` 分别从工作区复制到最终输出。生成资产在公共执行上仍是受控复制，但在所有权和清单上保持独立类别。`BuildManifestTracker` 把两类都并入现有资产清单，使旧派生物在配置删除、源文件删除、工具失败或格式/尺寸变化后按增量规则清理。

主题 tokens 保持现有直接生成合同；本轮不把它们迁入临时工作区。

### 5.4 移除 after-build 图片分支

- 从内建插件注册表移除 `ImageProcessingPlugin`。
- 删除或退役只服务该内建插件的 after-build 尺寸生成实现及专项夹具。
- 删除 `__image_srcsets` 写入；当前生产代码没有读取方，本轮不新增替代模板合同。
- 尺寸变体路径保持不变，因此直接引用这些静态路径的站点不需要迁移。
- 不在公共输出中引入 freshness sidecar；输出所有权由统一计划和构建清单负责。

通用 after-build 插件机制及其他插件输出跟踪保持不变。

## 6. 数据流

```text
主题源码 assets（只读）
        |
        v
独占临时工作区副本
        |
        +--> SCSS 编译 --> 临时 CSS 成功集
        |
        +--> 原图快照 --> 格式转换 + 尺寸生成 --> 临时图片成功集
        |
        v
候选内部冲突检查 + 完整 AssetOutputPlan 全局冲突检查
        |
        v
渲染与资产公共写入
        |
        v
统一 manifest 所有权、陈旧输出删除、工作区清理
```

公共输出写入之前，计划必须同时知道渲染路由、静态文件、普通主题资产、SCSS 输出、图片派生物、媒体和 tokens 的目标路径。

## 7. 错误、取消与清理

- 配置路径无效、候选目标重复或全局输出冲突：失败关闭，抛出稳定的配置/`BuildAssetOutputCollision` 诊断，不写任何公共资产。
- Sass 或图片工具缺失：记录现有 skip 警告；普通可发布资产继续，缺失派生物不进入计划。
- 单个转换失败：记录现有 error 警告；删除该临时文件，仅省略该派生物，不伪造成功所有权。
- 超时：外部工具运行器终止整个进程树并有界等待输出管道；不得因孙进程持有管道永久挂起。
- 用户取消：终止进程树、重新抛出取消，不降级为普通警告。
- 准备、规划、渲染或复制任一阶段失败：清理整个临时工作区。
- 清理遭遇 IO/权限错误：记录有界警告，不把构建错误报告为成功修复；不得为清理失败修改主题源码或公共目录外的其他路径。

## 8. 并发与确定性

- 资产准备在多语言分支启动前只执行一次。
- 准备完成后，所有语言变体只读共享准备结果。
- 工具输出文件名、目标路径排序和冲突比较使用现有平台输出身份比较器。
- 图片候选输入和输出均以稳定路径顺序处理；工具完成顺序不得影响计划顺序。
- 不以时间戳判断新鲜度。每次构建的临时工作区是新的，最终增量所有权由 manifest 指纹和当前计划决定。

## 9. 兼容性

保持：

- SCSS 默认输出目录 `assets`。
- 已配置 SCSS 的目标路径和相对层级。
- 全尺寸 WebP/AVIF 与原格式尺寸变体的既有公共文件名。
- 图片工具缺失或单项失败时的警告并继续语义。
- 通用插件 hook、第三方插件输出跟踪和非图片 after-build 行为。

明确移除：

- 主题源码旁的派生文件副作用。
- 公共输出内的二次图片扫描和递归派生。
- 内建图片插件的 `__image_srcsets` 私有数据。
- 任何仅靠已有文件时间戳或文件名就宣称派生物归 Bukit 所有的行为。

## 10. 测试策略

实施严格按 TDD 进行，每一行为先观察到与缺陷相符的 RED，再做最小生产修改。至少覆盖：

### 10.1 SCSS

- 设置 `entryPoint` 时只编译该文件。
- 未设置 `entryPoint` 时编译全部 SCSS，并保留相对层级。
- `outputDir` 相对于最终输出根目录。
- Sass 成功、缺失、失败和取消时主题源码均字节不变且无新增/删除文件。
- SCSS 启用时源码不进入公共输出。

### 10.2 图片

- 格式转换和尺寸生成都只修改临时工作区。
- 一次和连续两次构建均不会产生 `-480w-480w` 等递归派生。
- 只生成本设计列明的全尺寸格式与原格式尺寸集合。
- 同 stem/同目标候选在工具调用前失败。
- 图片派生物与静态、普通资产、渲染路由或 tokens 冲突时在公共写入前失败。
- 工具缺失、非零退出或零退出无输出时，该目标不在输出计划和 manifest 中。
- 删除源文件、删除尺寸/格式配置或本次工具失败时，旧的受管派生物被增量清理。
- 现有用户资产若占用派生目标，触发冲突且不被覆盖。

### 10.3 生命周期与集成

- 单语言和多语言构建均只准备一次资产工作区，变体只读共享。
- 准备成功、准备失败、规划冲突、渲染失败和取消后临时工作区均被清理。
- 内建插件图不再包含 `image-processing`，通用 after-build 插件仍执行。
- 生产代码不再写入或读取 `__image_srcsets`。

## 11. 验证边界

书面规格获批后，实施计划必须先用 `python3 scripts/checks/codex-workflow.py closure` 生成机器可读 verification closure，列明最终 changed files、直接消费者、序列化/公共合同消费者和精确专项命令，并解决全部 `unmapped`。随后用 `classify` 确认命令分类。

预计专项所有者为 `tests/Bukit.Engine.Tests/Bukit.Engine.Tests.csproj`；若最终 closure 因配置验证或插件图变更要求其他直接所有者测试，实施计划必须明确列出。不得运行 whole-solution、`scripts/test-all.sh`、`scripts/smoke-all.sh`、release/full gate、`post-change-*` 或未命名审计。

生产修改和完整专项测试结束后只做一次专项审查；仅 Critical/Important 发现进入修复和定向复审。全部 P0 任务结束后按仓库规则做一次 delta-only 统一复核，不重跑未失效证据。

## 12. 实施顺序

1. 重新核对 HEAD、重叠工作树和 verification closure；有重叠未解决则停止写入。
2. 以 RED 测试固定图片候选、统一计划所有权和插件移除合同。
3. 扩展准备结果与 `AssetOutputPlan`，把格式和尺寸派生物统一纳入临时准备与公共复制。
4. 移除内建 after-build 图片分支和死数据，保留通用插件机制。
5. 运行精确专项 GREEN、一次专项审查和 delta-only P0 复核。

每一步只处理本规格中的 P0 合同；发现 P1/P2 或相邻缺陷只记录，不顺手修复。

## 13. 验收标准

P0 仅在以下证据全部成立时完成：

- 主题源码在 SCSS 和图片处理的成功、失败、超时、取消路径均保持不变。
- `entryPoint` 与 `outputDir` 按第 4 节生效。
- 图片格式与尺寸派生物都在临时工作区生成，并在公共写入前经过统一冲突检查。
- 公共输出不产生递归尺寸文件，不存在内建 after-build 图片处理或 `__image_srcsets`。
- 成功派生物由资产 manifest 跟踪；失败、删除和配置变化后的陈旧派生物被清理。
- 多语言构建没有共享源码写入或派生物竞态。
- machine-readable closure 无 `unmapped`，所有明确专项测试 fresh GREEN，专项审查无 Critical/Important。
- 没有 P1/P2、Labs、WeChat、CI、发布、门禁或历史参考目录的越界修改。
