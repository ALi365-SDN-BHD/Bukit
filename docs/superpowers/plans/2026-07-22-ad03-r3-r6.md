> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close AD-03 residual findings R3–R6 without changing Bukit Core 1.x public signatures or promoting the Notion assemblies to external NuGet SDKs.

**Architecture:** Canonical Notion endpoint and rendering ownership stays in `Bukit.Notion`; Bukit-specific projection stays in `Bukit.Content.Notion`; `Bukit.Content` owns the 1.x internal bridge consumed by Engine. Legacy public facades remain binary-compatible while architecture tests prevent canonical code from depending back on them.

**Tech Stack:** .NET 10, C#, xUnit, SDK-style project references, repository focused/targeted shell gates.

## Global Constraints

- Preserve every existing 1.x public signature, namespace, assembly identity, configuration schema, plugin protocol, Notion API version, content projection, HTML, relation link, and cache format.
- Do not change HTTP retry semantics, `HttpClient` ownership, token headers, per-client throttling, error redaction, or cancellation propagation.
- Do not introduce reflection-based JSON serialization or runtime reflection mapping.
- Do not add NuGet package metadata, publishing workflows, or installation documentation.
- Do not modify AD-01, AD-05, analyzer baselines, or unrelated architecture debt.
- Run `post-change-focused.sh` once after each code subtask. Run `post-change-targeted.sh --base 5632b1db` exactly once after the aggregate diff.
- Do not run full/release gates, `scripts/test-all.sh`, `scripts/smoke-all.sh`, or whole-solution tests.

```csharp
using Bukit.Engine.Abstractions.Content;

namespace Bukit.Content.Notion;

internal sealed record NotionCompatibilityPage(
    string PageId,
    string Title,
    string Slug,
    string NotionUrl,
    IReadOnlyDictionary<string, ContentField> Fields);

internal static class NotionCompatibilityQueries
{
    internal static async Task<NotionCompatibilityPage> FetchPageAsync(
        NotionApiClient client,
        string pageId,
        CancellationToken cancellationToken)
    {
        ArgumentNullException.ThrowIfNull(client);
        var page = await NotionPageQuery.FetchAsync(client.Transport, pageId, cancellationToken);
        return new(page.PageId, page.Title, page.Slug, page.NotionUrl, page.Fields);
    }

    internal static Task<IReadOnlyDictionary<string, IReadOnlyList<string>>> ReadDatabaseOptionsAsync(
        NotionApiClient client,
        string databaseId,
        CancellationToken cancellationToken)
    {
        ArgumentNullException.ThrowIfNull(client);
        return NotionDatabaseOptionReader.ReadAsync(client.Transport, databaseId, cancellationToken);
    }

    internal static string NormalizeFieldKey(string text)
        => NotionDatabaseOptionReader.NormalizeFieldKey(text);
}
```

Refactor `NotionDatabaseOptionReader` so its existing Content-client overload and a new canonical `NotionClient` overload share one private parser. The canonical overload wraps `NotionApiException` as the same `ContentException` shape and never disposes the passed client.
