# Bukit Theme Development

## Overview

A Bukit theme = `layouts/` + `assets/` + `static/` + `theme.yaml` + `theme` config section, working together to form the complete visual layer. Division of labor with `bukit-templating`: this skill covers "how to organize a theme, where to put CSS, how to reference assets, how to create/share/install themes"; `bukit-templating` covers "how to write Scriban syntax".

This skill also covers theme eco-system operations: **theme creation** (`create`, `wizard`), **theme discovery** (`list`, `info`, `params`), **theme distribution** (`pack`, `install`), **theme registry** (`search`), and **template-level management** (`template create/list/show/validate/snippets/hints/sync`).

**REQUIRED BACKGROUND:** The theme config section is in site.yaml's `theme` node — you must understand the Theme configuration model in bukit-config first.
**REQUIRED SUB-SKILL:** Verify theme integrity with `bukit doctor`. CLI commands reference bukit-cli-reference.

## Directory Structure

### Default Layout (generated by `bukit init`)

```
themes/<name>/
  layouts/                  ← Scriban templates
    layouts/                ← Layout templates (base.html)
    pages/                  ← Page templates (page, post, index, list)
    partials/               ← Partial templates (header, footer)
  assets/                   ← Processable assets (e.g., SCSS → CSS)
    style.css               ← Default stylesheet
  static/                   ← Static files (copied directly to output)
```

`bukit init` generates `themes/starter/` as the recommended content-site starting point. It is no longer just a minimal test scaffold: it includes a responsive CSS foundation, reusable card/list partials, and optional templates for pagination, taxonomy, and search.

Starter is inject-first for SEO. Its base layout should provide a normal `<head>` but should not include `partials/seo.html` or `partials/analytics.html` by default. Bukit injects canonical, description, robots, OG/Twitter, hreflang, JSON-LD, and GA4 when `site.seo.renderMode: inject`. The SEO/Analytics partials may still exist as reference partials for users who intentionally switch to `renderMode: theme`.

### `layouts/` — Template Directory

| File | Responsibility | Required |
|------|------|---------|
| `layouts/base.html` | Base layout (HTML skeleton) | **Yes** |
| `pages/page.html` | Generic page template | **Yes** |
| `pages/post.html` | Post template | **Yes** |
| `pages/index.html` | Homepage template | **Yes** |
| `pages/list.html` | List page template | **Yes** |
| `partials/header.html` | Navigation partial | No |
| `partials/footer.html` | Footer with Powered by bukit | **Strongly recommended** |
| `partials/list-card.html` | Reusable list item/card partial | Recommended |
| `partials/pagination-nav.html` | Reusable pagination nav partial | Recommended when pagination is enabled |
| `partials/seo.html` | Optional explicit SEO partial for `renderMode: theme`; not included by starter base in inject mode | Optional |
| `partials/analytics.html` | Optional explicit GA4 partial for `renderMode: theme`; not included by starter base in inject mode | Optional |

### `assets/` — Asset Directory

During build, files under the assets directory are **copied** to the output's `assets/` directory. Suitable for CSS, JS, fonts, and other frontend assets.

Referenced in HTML: `<link href="{{ site.base_url }}/assets/style.css" rel="stylesheet">`

### `static/` — Static File Directory

During build, files are **copied as-is** directly to the output root. Suitable for `robots.txt`, `favicon.ico`, and independent files not affected by the theme.

Difference from `assets/`: `assets/` files go under the `assets/` subdirectory; `static/` files go directly to the output root.

## Theme Configuration (theme section)

```yaml
theme:
  name: starter               # Theme name = themes/<name>/
  layouts: layouts            # Template subdirectory name
  assets: assets              # Asset subdirectory name
  static: static              # Static file subdirectory name
  params:                     # Theme params (optional)
    primary_color: "#0b5fff"
    footer_text: "Powered by bukit"
```

### Path Resolution Rules

| Condition | layouts path | assets path |
|------|-------------|-------------|
| `name` set + subdir at default | `themes/<name>/layouts/` | `themes/<name>/assets/` |
| `name` not set + subdir at default | `./layouts/` | `./assets/` |
| Subdir overridden to non-default | Relative to site root | Relative to site root |

In short: when `theme.name` is set, default subdirectory names automatically point to the corresponding directories under `themes/<name>/`. Overriding subdirectory names uses absolute paths from the site root.

## Theme Parameters (theme.params)

```yaml
theme:
  params:
    primary_color: "#0b5fff"
    nav_items:
      - { label: "Home", url: "/" }
      - { label: "Blog", url: "/blog/" }
    show_footer: true
```

Access in templates:
```html
<style>
:root { --primary: {{ site.params.primary_color }}; }
</style>

{{ if site.params.show_footer }}
<footer>{{ site.params.footer_text }}</footer>
{{ end }}
```

## Building a Theme from Scratch

## Recommended Starter Customization Workflow

When a user asks to make a Bukit theme easier to customize or wants a theme based on starter:

1. Start from `themes/starter/` generated by `bukit init`, or run `bukit theme create <name>` to create a separate custom theme.
2. Capture the user's intent in plain terms: site type, brand name, color direction, homepage sections, navigation items, and footer text.
3. Apply simple branding first through `theme.params`:

```yaml
theme:
  name: starter
  params:
    brand: My Site
    footer_text: My Site
```

4. Change visual identity through CSS variables in `assets/style.css` before editing templates.
5. Keep SEO engine-owned unless the user explicitly asks for theme-owned head output. For starter-derived themes, prefer `site.seo.renderMode: inject` and do not add SEO/Analytics partial includes to `layouts/base.html`. If switching to `renderMode: theme`, use the generated partials and keep HTML attributes escaped.
6. Change shared chrome through `layouts/partials/header.html` and `layouts/partials/footer.html`.
7. Edit page templates only when structure changes:
   - `layouts/pages/index.html` for the homepage
   - `layouts/pages/list.html` for collection lists
   - `layouts/pages/post.html` for articles
   - `layouts/pages/page.html` for pages
7. Keep `layouts/bukit.templates.yaml` in sync when adding/removing optional templates or changing list page content requirements.
8. Verify with `bukit doctor`, then `bukit build`, then preview the output.

### CLI Theme Creation

Use this when a user wants a new reusable theme directory:

```bash
# Simple creation (copy from built-in starter)
bukit theme create <name> \
  --brand "My Site" \
  --primary-color "#0b5fff" \
  --accent-color "#0f7b6c" \
  --use

# Interactive wizard (Q&A-based, full customization)
bukit theme wizard my-blog

# Quick creation with preset
bukit theme wizard my-blog --preset blog
bukit theme wizard my-docs --preset docs
bukit theme wizard saas-landing --preset landing
bukit theme wizard text-only --preset minimal
bukit theme wizard gallery --preset portfolio
```

Behavior:
- Default source is the built-in starter scaffold.
- `--from <existing-theme>` copies an existing local `themes/<existing-theme>/`.
- `--use` writes `theme.name` back to the selected config.
- `--force` replaces an existing destination theme directory; use only when the user clearly wants replacement.
- `--brand`, `--primary-color`, and `--accent-color` seed the theme params and CSS variables so the first result is already branded.

## Theme Self-Description (theme.yaml)

Every theme generated by `bukit theme create` or `bukit theme wizard` includes a `theme.yaml` at the theme root (`themes/<name>/theme.yaml`). This is an optional but recommended convention:

```yaml
name: my-theme
version: 1.0.0
description: A clean blog theme
author: Ali
license: MIT
tags: [blog, minimal, dark-mode]
requires_bukit: ">=2.0.0"
params:
  - key: primary_color
    label: Primary Color
    type: color
    default: "#0b5fff"
```

`theme.yaml` powers:
- **`bukit theme list`** — shows version, description, tags, param count
- **`bukit theme info <name>`** — full details including params and template file list
- **`bukit theme params [name]`** — lists only the customizable parameters
- **`bukit theme pack`** — uses `version` to name the output archive
- **`bukit doctor`** — `ConfigValidator.ValidateThemeYaml()` optionally validates the file

## Theme Wizard Presets

`bukit theme wizard` supports 5 built-in presets (defined in `WizardPresets.cs`):

| Preset | Scenario | Key Characteristics |
|--------|----------|-------------------|
| `blog` | Personal blog with sidebar and tag cloud | Inter font, CardHoverLift, DarkMode, 720px content width |
| `docs` | Documentation site with left navigation | Fira Code, StickyHeader, SmoothScroll, 800px content width |
| `landing` | Single-page landing with Hero + Features + CTA | HeroCta button, ScrollShrinkNav, AnimateOnScroll, 960px content |
| `minimal` | Ultra-minimal text-only site | Georgia serif, no behaviors, minimal layout, 680px content |
| `portfolio` | Photo/art portfolio with gallery | Dark background, DM Sans headings, CardHoverLift, 1200px content |

Usage:
```bash
# Direct preset (minimal Q&A — only override color + dark mode)
bukit theme wizard my-site --preset blog

# Interactive preset picker (shows 5 presets + "None" option)
bukit theme wizard my-site
```

## 主题继承 (Theme Inheritance)

子主题可继承父主题的模板、静态文件和资源，实现主题的级联覆盖。

### 配置

```yaml
theme:
  name: my-child-theme
  extends: parent-theme-name
```

### 级联规则

- **模板查找**：子主题优先 → 父主题回退（`{% layout %}`, `{{ include }}` 等指令自动级联）
- **静态文件**：子主题 `static/` 先复制 → 父主题 `static/` 后复制（子覆盖父）
- **资源文件**：子主题 `assets/` 先复制 → 父主题 `assets/` 后复制

### 使用场景

- 基于官方主题自定义少量模板
- 多站点共享公共主题基础
- 渐进式主题升级

## 组件 (Components)

在 `site.yaml` 中声明可复用模板组件，在 Scriban 中调用。

### 声明组件

```yaml
theme:
  components:
    PostCard:
      template: "partials/post-card.html"
      props:
        title: ""
        url: ""
```

### 组件模板

```html
{{!-- themes/<name>/layouts/partials/post-card.html --}}
<div class="post-card">
  <h3>{{ title }}</h3>
  <a href="{{ url }}">Read more</a>
</div>
```

### 在模板中使用

```
{{ comp.render "PostCard" page.title page.url }}
```

组件继承父模板的全局变量（`page`, `site` 等），props 按声明顺序绑定。

## 图片优化 (Image Optimization)

构建时自动转换 WebP/AVIF 格式，需要系统安装 `cwebp` 或 `magick`（ImageMagick）CLI。

### 配置

```yaml
theme:
  images:
    enabled: true
    formats: [webp]
    sizes: [480, 768, 1200]
    quality: 85
```

### 模板中使用 srcset

```html
<img src="/assets/hero.webp"
     srcset="{{ ImageOptimizer.BuildSrcset '/assets/hero' sizes 'webp' }}"
     alt="Hero" />
```

没有安装转换工具时优雅降级（跳过 + 警告）。

## SCSS 编译

自动编译 `.scss` → `.css`，需要系统安装 `sass` 或 `dart-sass` CLI。

### 配置

```yaml
theme:
  scss:
    enabled: true
```

在 `assets/` 目录下编写 `.scss` 文件，构建时自动编译为 `.css`（编译成功后删除原 `.scss` 文件）。未安装 CLI 时优雅降级。

## Theme Distribution & Ecosystem

### Pack a theme for sharing
```bash
bukit theme pack my-blog          # → my-blog-1.0.0.tar.gz
bukit theme pack                   # packs active theme (from site.yaml)
bukit theme pack my-blog --output ./releases/
```

### Install a theme
```bash
# From local archive
bukit theme install ./my-blog-1.0.0.tar.gz

# From URL
bukit theme install https://github.com/user/bukit-theme/releases/download/v1.0/theme.tar.gz

# From community registry
bukit theme install --registry blog-clean
```

### Search community themes
```bash
bukit theme search                 # list all
bukit theme search blog            # filter by name/tags/description
bukit theme search --refresh       # force refresh cache
```

## Template Snippet Library

Built-in snippet library (`TemplateSnippets.cs`) for quick template content:

```bash
bukit template snippets            # list all available snippets
bukit template snippets post-card  # show specific snippet (Scriban + CSS)
```

**Scriban snippets (8):** post-card, tag-cloud, toc, share-buttons, comments-placeholder, breadcrumb, related-posts, author-bio

**CSS snippets (9):** post-card, tag-cloud, toc, btn (btn-primary/btn-outline/btn-sm/btn-lg), nav-breadcrumb, share-buttons, callout (info/warning/danger/success), responsive-table, code-block

### Minimal Custom Theme

Create the directory structure:
```
themes/my-theme/
  layouts/
    layouts/base.html
    pages/
      page.html
      post.html
      index.html
      list.html
  assets/
    style.css
  static/
    favicon.ico
```

Configure site.yaml:
```yaml
theme:
  name: my-theme
```

### Required Template Checklist

| Template Path | Minimum Requirement |
|---------|---------|
| `layouts/base.html` | Must contain `{{ content }}` placeholder |
| `pages/page.html` | Must start with `{% layout "layouts/base.html" %}` |
| `pages/post.html` | Like page, typically displays date |
| `pages/index.html` | Iterates over `pages` list |
| `pages/list.html` | Iterates over `pages` list |

Verify: `bukit doctor` checks that these files exist and parse correctly.

## Default Theme Anatomy

Default theme structure generated by `bukit init --template minimal`:

```
themes/starter/
  layouts/
    layouts/base.html       ← HTML skeleton, {{ include }} header/footer
    pages/page.html         ← Page: title + content
    pages/post.html         ← Post: title + date + content
    pages/index.html        ← Home: title + page list
    pages/list.html         ← List: page link list
    pages/pagination.html   ← Generated paginated archive template
    pages/search.html       ← Generated search page template
    pages/taxonomy-index.html / taxonomy-term.html
    partials/header.html    ← Navigation bar
    partials/footer.html    ← Footer
    partials/list-card.html ← Shared card/list rendering
    partials/pagination-nav.html
    bukit.templates.yaml    ← Template capability manifest
  assets/
    style.css               ← Full default styles (layout, cards, content, Notion blocks)
```

The default CSS covers: responsive layout, navigation, cards, typography, tables, Callout, Toggle, code blocks, blockquotes, video embeds, math formulas, Notion color system, column layouts, and more. Override CSS variables and shared components before starting from scratch.

## Referencing Static Assets

Correct way to reference assets in templates:

```html
<!-- CSS -->
<link href="{{ site.base_url }}/assets/style.css" rel="stylesheet">

<!-- JS -->
<script src="{{ site.base_url }}/assets/main.js"></script>

<!-- Image (inside assets directory) -->
<img src="{{ site.base_url }}/assets/logo.svg">

<!-- Files in static directory: go directly to root, do NOT add /static/ prefix -->
<link rel="icon" href="{{ site.base_url }}/favicon.ico">
```

## Footer — Powered by bukit

Every Bukit theme must include a footer partial with a "Powered by bukit" attribution, where "bukit" is a hyperlink to the Bukit GitHub repository.

**Canonical `partials/footer.html`:**

```html
<footer>
  <small>Powered by <a href="https://github.com/ALi365-SDN-BHD/Bukit" target="_blank" rel="noopener">bukit</a></small>
</footer>
```

- The `<a>` tag must point to `https://github.com/ALi365-SDN-BHD/Bukit`
- `target="_blank"` and `rel="noopener"` are recommended for external links
- This partial is included in `layouts/base.html` via `{{ include "partials/footer.html" }}`
- The footer text can be customized via `theme.params` (e.g., `footer_text`) but the bukit attribution link must remain

## Common Errors

| Symptom | Cause | Fix |
|---------|------|------|
| Theme switch not taking effect | `theme.name` in site.yaml not updated | `bukit theme use <name>` or edit manually |
| Template not found (doctor reports Missing templates) | Missing 5 required templates under layouts dir | Ensure base.html and 4 page templates exist |
| CSS 404 | Asset path or `assets`/`static` dir config incorrect | Check template reference paths start with `{{ site.base_url }}/assets/` |
| static files not output | static dir path config incorrect | Check that `theme.static` points to the correct directory |
| `theme.params` empty in templates | params not defined in site.yaml or key name typo | Verify `site.params.xxx` matches site.yaml |
| Templates not found after customizing layouts_dir | Custom value without `layouts` won't auto-point to `themes/<name>/` | Custom values resolve from site root; confirm the path exists |
| `doctor` reports heuristic fallback | List page template static analysis cannot determine if content is needed | Create `layouts/bukit.templates.yaml` and declare `needs_page_content` |
