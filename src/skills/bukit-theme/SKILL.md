# Bukit 主题开发

## Overview

Bukit 主题 = `layouts/` + `assets/` + `static/` + `theme` 配置节，四者协同构成完整视觉层。与 `bukit-templating` 的分工：本技能讲"主题怎么组织、CSS 放哪、资源怎么引用"；`bukit-templating` 讲"Scriban 语法怎么写"。

**REQUIRED BACKGROUND:** 主题配置节位于 site.yaml 的 `theme` 节点，必须先理解 bukit-config 中的 Theme 配置模型。
**REQUIRED SUB-SKILL:** 用 `bukit doctor` 验证主题完整性。CLI 命令参考 bukit-cli-reference。

## 目录结构

### 默认布局（`bukit init` 生成）

```
themes/<name>/
  layouts/                  ← Scriban 模板
    layouts/                ← 布局模板（base.html）
    pages/                  ← 页面模板（page, post, index, list）
    partials/               ← 局部模板（header, footer）
  assets/                   ← 需处理的资源（如 SCSS → CSS）
    style.css               ← 默认样式表
  static/                   ← 静态文件（直接复制到输出）
```

### `layouts/` — 模板目录

| 文件 | 职责 | 必须存在 |
|------|------|---------|
| `layouts/base.html` | 基础布局（HTML 骨架） | **是** |
| `pages/page.html` | 普通页面模板 | **是** |
| `pages/post.html` | 文章模板 | **是** |
| `pages/index.html` | 首页模板 | **是** |
| `pages/list.html` | 列表页模板 | **是** |
| `partials/header.html` | 导航栏局部 | 否 |
| `partials/footer.html` | 页脚局部 | 否 |

### `assets/` — 资源目录

构建时，assets 目录下的文件会被**复制**到输出目录的 `assets/` 下。适合放 CSS、JS、字体等前端资源。

HTML 中引用：`<link href="{{ site.base_url }}/assets/style.css" rel="stylesheet">`

### `static/` — 静态文件目录

构建时直接**原样复制**到输出根目录。适合放 `robots.txt`、`favicon.ico`、不受主题影响的独立文件。

与 `assets/` 的区别：`assets/` 走 `assets/` 子目录，`static/` 直接平铺到输出根。

## 主题定位（theme 配置节）

```yaml
theme:
  name: starter               # 主题名 = themes/<name>/
  layouts: layouts            # 模板子目录名
  assets: assets              # 资源子目录名
  static: static              # 静态文件子目录名
  params:                     # 主题参数（可选）
    primary_color: "#0b5fff"
    footer_text: "Powered by bukit"
```

### 路径解析规则

| 条件 | layouts 路径 | assets 路径 |
|------|-------------|-------------|
| `name` 已设置 + 子目录为默认值 | `themes/<name>/layouts/` | `themes/<name>/assets/` |
| `name` 未设置 + 子目录为默认值 | `./layouts/` | `./assets/` |
| 子目录被覆盖为非默认值 | 相对于站点根目录 | 相对于站点根目录 |

即：设了 `theme.name` 后，默认子目录名自动指向 `themes/<name>/` 下对应目录。覆盖子目录名则会使用站点根目录下的绝对路径。

## 主题参数 (theme.params)

```yaml
theme:
  params:
    primary_color: "#0b5fff"
    nav_items:
      - { label: "首页", url: "/" }
      - { label: "博客", url: "/blog/" }
    show_footer: true
```

模板中访问：
```html
<style>
:root { --primary: {{ site.theme.params.primary_color }}; }
</style>

{{ if site.theme.params.show_footer }}
<footer>{{ site.theme.params.footer_text }}</footer>
{{ end }}
```

## 从零搭建主题

### 最小自定义主题

创建目录结构：
```
themes/my-theme/
  layouts/
    layouts/base.html
    pages/
      page.html
      post.html
      index.html
      list.html
  assets/
    style.css
  static/
    favicon.ico
```

配置 site.yaml：
```yaml
theme:
  name: my-theme
```

### 必备模板清单

| 模板路径 | 最低要求 |
|---------|---------|
| `layouts/base.html` | 包含 `{{ content }}` 占位符 |
| `pages/page.html` | 以 `{% layout "layouts/base.html" %}` 开头 |
| `pages/post.html` | 同 page，通常显示日期 |
| `pages/index.html` | 遍历 `pages` 列表 |
| `pages/list.html` | 遍历 `pages` 列表 |

验证：`bukit doctor` 会检查这些文件是否存在且语法正确。

## 默认主题解剖

`bukit init --template minimal` 生成的默认主题结构：

```
themes/starter/
  layouts/
    layouts/base.html       ← HTML 骨架，{{ include }} header/footer
    pages/page.html         ← 单页：标题 + content
    pages/post.html         ← 文章：标题 + 日期 + content
    pages/index.html        ← 首页：标题 + 页面列表
    pages/list.html         ← 列表：页面链接列表
    partials/header.html    ← 导航栏
    partials/footer.html    ← 页脚
  assets/
    style.css               ← 完整默认样式（含 Notion callout/table/toggle 等）
```

默认 CSS 已覆盖：排版、表格、Callout、Toggle、代码块、引用、视频嵌入、数学公式、Notion 色彩系统、分栏布局等。在默认样式基础上按需覆盖即可，无需从头写。

## 引用静态资源

模板中引用资源的正确姿势：

```html
<!-- CSS -->
<link href="{{ site.base_url }}/assets/style.css" rel="stylesheet">

<!-- JS -->
<script src="{{ site.base_url }}/assets/main.js"></script>

<!-- 图片（assets 目录内） -->
<img src="{{ site.base_url }}/assets/logo.svg">

<!-- static 目录内的文件：直接平铺到根，不要加 /static/ 前缀 -->
<link rel="icon" href="{{ site.base_url }}/favicon.ico">
```

## 常见错误

| 错误现象 | 原因 | 修复 |
|---------|------|------|
| 主题切换不生效 | site.yaml 中 `theme.name` 未更新 | `bukit theme use <name>` 或手动修改 |
| 模板找不到 (doctor 报 Missing templates) | layouts 目录下缺少必备的 5 个模板 | 确保 base.html 和 4 个 page 模板存在 |
| CSS 404 | 资源路径或 `assets`/`static` 目录配置错误 | 检查模板引用路径是否以 `{{ site.base_url }}/assets/` 开头 |
| static 文件未输出 | static 目录路径配置错误 | 检查 `theme.static` 是否指向正确目录 |
| `theme.params` 在模板中为空 | site.yaml 中未定义 params 或键名拼写错误 | 检查 `site.theme.params.xxx` 的 xxx 与 site.yaml 一致 |
| layouts_dir 改为自定义值后模板找不到 | 自定义值不含 `layouts` 时不会自动指向 `themes/<name>/` | 自定义值从站点根目录解析，确认路径存在 |
| `doctor` 报 heuristic fallback | 列表页模板静态分析无法确认是否需要 content | 创建 `layouts/bukit.templates.yaml` 并声明 `needs_page_content` |
